### 一句话

网络传输的本质是：**把数据切成包，一层层套上信封，发出去，对方一层层拆开。**

套信封的过程叫**封装**，拆信封叫**解封装**。

### 四层，各管一件事

| 层 | 管什么 | 关键标识 | 出问题的典型表现 |
| --- | --- | --- | --- |
| 应用层（HTTP/DNS/SSH） | 数据是什么意思 | URL、域名、端口语义 | 页面 404、DNS 解析失败 |
| 传输层（TCP/UDP） | 数据完整送到哪个程序 | 端口号 | 连接超时、connection refused |
| 网络层（IP） | 数据从哪台机器到哪台机器 | IP 地址 | ping 不通、路由不可达 |
| 链路层（以太网/Wi-Fi） | 相邻设备之间怎么走 | MAC 地址 | 網线没插、交换机端口坏 |

封装顺序是从上到下：

```text
[HTTP 请求头 + 正文]
→ 加 TCP 头（源端口/目标端口/序号）        = 段
→ 加 IP 头（源 IP/目标 IP）               = 包
→ 加以太网头（源 MAC/目标 MAC）            = 帧
→ 电信号/光信号发出去
```

对方收到后反过来一层层剥，剥到 HTTP 才交给浏览器。

> 记住封装的顺序，抓包时你才知道自己在看哪一层的头。

### 为什么要分层

因为**每层可以独立替换**。Wi-Fi 换成有线，IP 之上完全不用改；IPv4 换成 IPv6，HTTP 依然照旧。分层带来的另一个好处是排错：**先定位在哪一层，再看那一层的工具**。

### 排错时用这张表

```text
网站打不开
├─ DNS 解析不到？      → nslookup / dig 域名
├─ IP 通不通？         → ping IP
├─ 端口通不通？        → telnet IP 端口 / nc -vz
├─ HTTP 返回什么？     → curl -I URL
└─ 包到底到没到？      → tcpdump
```

从上往下逐层验证，**哪一层第一次不通，问题就在那一层及以上**。不要一上来就重启服务。

### 一个具体例子

你在浏览器打开 `https://wild-think-lab.github.io`，实际发生了：

1. 查 DNS：域名 → 一组 IP。
2. 和其中一个 IP 的 443 端口建立 TCP 连接（三次握手）。
3. 做 TLS 握手，协商加密。
4. 发 HTTP 请求，收 HTML。
5. 浏览器再发几十个请求拿图片、CSS。

**"打开很慢"可能卡在任意一步**。分不清步骤，就只能瞎猜；分清步骤，用 `curl -w` 就能量出各阶段耗时。

### 本章小结

- 网络 = 分层 + 封装，每层加自己的头。
- 四层：应用、传输、网络、链路，各有独立的排错工具。
- 排错从下往上，第一次不通的那一层就是答案所在。
