### 地址长什么样

```
2001:db8:0:1::/64
  ↑ 全局路由前缀（通常 /48 或 /56 给客户）
         ↑ 子网 ID（/64 是标准，因为 SLAAC 需要 64 位接口 ID）
```

**关键**：一个 /64 = 一台路由下的一个网段（不要切成 /80，会破坏 SLAAC）。

### 三类地址

```
::1              回环
fe80::/10        链路本地（每张网卡自动有，用于邻居发现）
2001:db8::/32    全局单播（公网可路由）
fc00::/7         唯一本地（类似私网）
```

**"没有 NAT"** 是 IPv6 的核心差异：每台设备都可直接有公网地址（靠防火墙保护）。

### SLAAC vs DHCPv6

```
SLAAC：路由器通告前缀，主机自己生成地址（无需服务器）
DHCPv6：集中分配 + 下发 DNS 等参数
```

**常见组合**：

```
SLAAC + DHCPv6（下放 DNS）或 RA 里直接带 DNS（RDNSS）
```

### Linux 上配双栈

```bash
ip -6 addr
ip -6 route
sysctl net.ipv6.conf.all.forwarding=1
```

```conf
# 静态
ip -6 addr add 2001:db8:0:1::10/64 dev eth0
ip -6 route add default via 2001:db8:0:1::1
```

### 双栈的优先级（"启用了反而更慢"）

```
系统默认偏好 IPv6（RFC 6724）
但 IPv6 路径可能不通（有 AAAA 记录却没有 IPv6 连通）
→ 应用先试 IPv6 超时再回退 IPv4 → 变慢
```

**排障**：

```bash
curl -6 -v https://example.com
curl -4 -v https://example.com
```

**"IPv4 快、IPv6 卡"** → 说明 IPv6 路径有问题（不是应用 bug）。

### 五个"上了 IPv6 出的问题"

**① 防火墙没配**

```
v6 默认可能放行更多 → 暴露面变大（ip6tables/nftables 要单独配）
```

**② 只有 AAAA 没有连通**

```
DNS 解析到 v6 但路径不通 → 访问慢/失败
```

**③ MTU / PMTU**

```
v6 不允许中间分片 → 依赖 ICMPv6 "packet too big"
ICMPv6 被防火墙拦 → 大包卡死
```

**④ 前缀变了**

```
运营商换前缀 → 内部地址/防火墙规则全失效（要动态处理）
```

**⑤ 老设备/应用不支持**

```
某些监控/老系统只认 v4 → 需要双栈过渡或 NAT64
```

### 排障顺序

```
1) ip -6 addr（有没有地址）
2) ping6 网关（链路通不通）
3) ping6 公网（路由通不通）
4) dig AAAA（解析对不对）
5) curl -6（应用层）
6) 检查 ICMPv6 是否被拦（PMTU 问题）
```

### 检查清单

```
□ 前缀规划（至少 /64 一个网段）
□ 有状态/无状态方案明确
□ v6 防火墙独立配置
□ 监控同时采集 v4/v6 可用性
□ 应用支持双栈或明确只走 v4
□ 关键路径测过 PMTU
□ 前缀变更的处理方式明确
□ 有"v6 不可用则回退"的验证
```
