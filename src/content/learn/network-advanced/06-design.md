### 设计从"清单"开始，不是从"设备"开始

```
① 要连哪些东西（服务器/办公终端/打印机/摄像头/无线）
② 各自要访问什么（互联网/内网服务/互相隔离）
③ 规模（数量、增长预期）
④ 可用性要求（能不能停）
```

**"先买设备再规划"** 是最常见的返工原因。

### 网段规划（一条实用规则）

```
① 按"角色"分段：服务器 / 办公 / 无线 / 管理 / IoT
② 每段预留 2–4 倍增长空间
③ 服务器段单独，不与办公混
④ 管理段（带外/BMC/IPMI）必须独立且禁止出网
```

**示例**：

| 用途 | 网段 | VLAN |
| --- | --- | --- |
| 管理（BMC/交换机） | 10.10.0.0/24 | 100 |
| 服务器 | 10.20.0.0/22 | 200 |
| 办公 | 10.30.0.0/23 | 300 |
| 无线（员工） | 10.40.0.0/23 | 400 |
| 无线（访客） | 10.41.0.0/24 | 401 |
| IoT/摄像头 | 10.50.0.0/24 | 500 |

**"访客网必须与内网隔离，只给出网"**。

### 地址分配

```
① 服务器：静态（或 DHCP 保留）
② 办公：DHCP
③ 管理：静态
④ IoT：DHCP + 与业务隔离
```

**"网关地址统一用 .1 或 .254"** 选一个并坚持（减少混乱）。

### 出口设计

```
单出口：简单，有单点
双出口：主备（策略路由/浮动默认路由）
```

**NAT 与策略**：

```
① 内网 → 互联网：SNAT
② 外网 → 内部服务：DNAT（只开放必要端口）
③ 内部服务器互访：不走 NAT（直连路由）
```

**"内部互访也走 NAT"** 会让日志全部失真（看不到真实源 IP）。

### 冗余（按预算分级）

```
网络层：双交换机（堆叠/VRRP）+ 双上联
出口：双线路（不同运营商）
电源：双电源（至少交换机双电）
```

**"只有一条线路"** 就别承诺"高可用"。

### 安全基线（网络侧）

```
① 管理口不暴露公网
② 交换机/防火墙管理走独立网段 + 强认证
③ 默认拒绝 + 白名单
④ 关闭未使用端口
⑤ 变更留记录（谁改了什么）
```

### 一张"图纸清单"

```
□ 拓扑图（设备/链路/带宽）
□ 网段与 VLAN 表
□ 地址分配表（谁用哪个段）
□ 出口与 NAT 规则清单
□ 防火墙策略清单（源/目的/端口/用途/负责人）
□ 冗余说明（哪些环节是单点）
□ 监控点（哪些设备/端口接监控）
□ 变更流程与回滚
```

**"策略清单带负责人"** 是半年后还能维护的关键。

### 三个"设计时想不到、上线后天天遇到"

**① 无线与有线不隔离**

```
访客连 Wi-Fi 就能扫内网 → 必须 VLAN 隔离 + 策略
```

**② 摄像头/IoT 在内网**

```
一个弱口令设备 = 内网入口 → IoT 单独段 + 只允许必要出网
```

**③ 没有"临时接入"方案**

```
临时设备（调试笔记本/供应商设备）随便插 → 破坏隔离
→ 预留一个"临时段"，用完关掉
```

### 小结

```
① 从需求清单开始，不从设备开始
② 按角色分段，预留增长
③ 管理段独立，访客段隔离
④ 内部互访不走 NAT
⑤ 冗余按预算分级，不承诺做不到的
⑥ 图纸清单要带负责人
```
