### 接入层要解决的四件事

```
① 端口够用（工位 + 预留 30%）
② 供电（POE 给 AP/摄像头/话机）
③ 隔离（访客/办公/IoT 分 VLAN）
④ 可管理（远程看端口状态与流量）
```

### VLAN 规划（一个办公网的例子）

```
VLAN 10  办公（192.168.10.0/24）
VLAN 20  访客（192.168.20.0/24，只出公网）
VLAN 30  IoT/摄像头（192.168.30.0/24，禁止访问互联网或只允许 NTP）
VLAN 40  服务器/管理（192.168.40.0/24，仅运维可访问）
```

**"全在一个网段"** → 广播风暴 + 无法隔离。

### 端口配置（交换机侧）

```bash
# 接终端（access）
switchport mode access
switchport access vlan 10
spanning-tree portfast

# 接 AP/交换机（trunk）
switchport mode trunk
switchport trunk allowed vlan 10,20,30
```

**"AP 口没配 trunk"** → 只有管理 VLAN 能过，终端上不了网。

### POE 预算

```
每个 AP 约 10–20W，摄像头 5–10W
交换机 POE 总功率要 ≥ 所有设备之和 × 1.2
```

**"POE 超预算"** → 后接入的设备供电失败（时好时坏，最难查）。

### 无线组网三种

```
① 面板 AP / 吸顶 AP + AC（有线回程，最稳）
② Mesh（无线回程，方便但带宽减半）
③ 路由一体（小场景）
```

**"大办公室用 mesh 无线回程"** → 人多就卡。

### 五个"办公室网络慢"

```
① 出口带宽被占满（备份/视频/大文件）
② 空口拥挤（2.4G 用户太多）
③ 交换机上行是百兆（内网互传慢）
④ 广播风暴（环路没开 STP）
⑤ DNS 慢（解析超时，感觉"网慢"）
```

### 环路：最容易致命的低级问题

```bash
# 看 STP 是否开启、是否有端口被 block
show spanning-tree
```

**"插了一根网线就全网瘫"** = 环路 + 没 STP。

### 一个"够用"的接入层清单

```
① 交换机可管理（能看端口/流量/VLAN）
② 端口预留 30%
③ POE 预算留 20%
④ VLAN 至少分：办公/访客/管理
⑤ 开 STP（或环回检测）
⑥ AP 有线回程
⑦ 有端口级监控（谁在打满）
```

### 检查清单

```
□ 端口数量与预留
□ POE 功率预算
□ VLAN 划分（办公/访客/IoT/管理）
□ 上行链路千兆以上
□ STP 开启
□ AP 有线回程优先
□ 有端口流量监控
□ 访客网络隔离
□ 有"新设备接入"流程
□ 有配线标签与文档
```
