### VRRP 在做什么

```
两台路由器共享一个"虚拟 IP"（VIP）作为网关
主设备持有 VIP 并转发；主挂了，备接管
```

**关键**：终端只配置 VIP 作为网关，切换对终端透明。

### Keepalived 最小配置

```conf
vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100            # 备机 90
    advert_int 1
    authentication { auth_type PASS; auth_pass secret }
    virtual_ipaddress { 192.168.1.100/24 }
}
```

**要点**：

```
① virtual_router_id 同网段不能重复
② priority 差至少 10（避免抖动）
③ 备机 state 也写 BACKUP（不要两个 MASTER）
```

### 心跳与脑裂

```
心跳：两台之间互发通告（组播/单播）
脑裂：心跳断了，两台都以为自己是主 → 同时持有 VIP
```

**防脑裂**：

```
① 心跳走独立链路（不要与业务共用）
② 加"仲裁"（第三方探活/ fencing）
③ 有"双主检测"告警
```

**"两边都有 VIP"** 是最危险的状态（VIP 冲突、流量乱跳）。

### 双机热备的真实难点

```
① 状态同步（会话/连接跟踪）
② 数据同步（如数据库要主从）
③ 切换时间（秒级 vs 分钟级）
④ 回切策略（自动回切还是手工）
```

**"只做 VIP 切换"** → TCP 连接全断（用户需要重连）。

### 会话保持（比 VIP 更难）

```
conntrack 同步（keepalived 可配）→ 已建立连接也能续
或"上层无状态 + 客户端重试"
```

**"切换后用户要重新登录"** → 会话没同步。

### 切换验证清单（必须做）

```
① 手工停主（systemctl stop keepalived）
② 备机是否接管（ip addr 看到 VIP）
③ 终端 ping 网关是否恢复（多久）
④ 业务请求是否恢复（多久）
⑤ 主恢复后是否"抢回"（回切策略）
⑥ 日志里切换原因是否记录
```

**"没演练过的高可用"** 等于没有。

### 五个"切换后不恢复"

**① 上游交换机 ARP 缓存没更新**

```
VIP 换到备机，但交换机还发往旧 MAC
→ 依赖 GARP（keepalived 会发，但要确认未被过滤）
```

**② 服务没跟着起**

```
VIP 切了，但 nginx 在备机没配好
```

**③ 数据不同步**

```
读到的数据是旧的
```

**④ 防火墙/安全组**

```
备机没放行，或云上弹性 IP 没绑
```

**⑤ 双主（脑裂）**

```
流量随机分布，时好时坏
```

### 一个"分层"的高可用设计

```
接入层：双上行 + STP/堆叠
网关层：VRRP（VIP）
应用层：多副本 + LB（健康检查）
数据层：主从/集群 + 切换预案
```

**"只做一层高可用"** → 其他层仍是单点。

### 检查清单

```
□ VIP 规划不与现有地址冲突
□ VRRP id/优先级正确
□ 心跳独立链路
□ 有防脑裂措施
□ 会话/连接同步方案明确
□ 服务随 VIP 一起切换（脚本）
□ 上游 ARP 刷新验证过
□ 切换演练过（含回切）
□ 有双主检测告警
□ 有切换耗时记录（对照 RTO）
```
