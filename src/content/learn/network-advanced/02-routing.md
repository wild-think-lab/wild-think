### 路由表就是"一张决策表"

```bash
ip route
# default via 10.0.0.1 dev eth0
# 10.0.0.0/24 dev eth0
# 172.16.0.0/16 via 10.0.0.2
```

**发一个包时**：

```
① 取出目的 IP
② 在路由表里找"匹配的网段"
③ 有多个匹配 → 选"前缀最长"的（最长前缀匹配）
④ 都不匹配 → 用默认路由
⑤ 没有默认路由 → "Network is unreachable"
```

### 最长前缀匹配的例子

```
路由表里同时有：
  10.0.0.0/8      → 网关 A
  10.1.0.0/16     → 网关 B
  10.1.2.0/24     → 网关 C

目标 10.1.2.5 → 命中 /24（最长）→ 走网关 C
目标 10.1.3.5 → 命中 /16 → 走网关 B
目标 10.2.0.5 → 命中 /8 → 走网关 A
```

**"路由写着却不通"** → 先确认"命中的是不是你以为的那条"。

```bash
ip route get 10.1.2.5      # 直接问内核"这个目的走哪条"
```

**`ip route get` 是最好用的路由排查命令**。

### 默认网关

```
default via 10.0.0.1
含义：所有"没有更具体匹配"的流量走这里
```

**三个常见问题**：

```
① 没有默认路由 → 出不了网
② 默认路由指向错 IP → 全部丢包
③ 多张网卡都有默认路由 → 按 metric 选，可能选错
```

```bash
ip route show default
# 有多条时看 metric
```

### 转发与 NAT

```
主机要"把别人的包转发出去" → 需要 ip_forward=1
```

```bash
echo 1 > /proc/sys/net/ipv4/ip_forward
# 持久化：/etc/sysctl.d/99-forward.conf
```

**"内网能 ping 通网关但上不了网"**：

```
① 没开 ip_forward（网关机）
② 没做 NAT（出口需要地址转换）
③ DNS 没配
```

### 三个"配了路由还不通"

**① 回程路由缺失**

```
A → B 的包能到，B 不知道回 A 的路
→ 单向不通（"能请求不能响应"）
```

**"ping 不通"要看两个方向**，这是最经典的排查盲点。

**② 路由写在了错误的接口/命名空间**

```
容器/策略路由场景，路由表可能有多张
ip route show table all
```

**③ 防火墙 DROP**

```
路由正确但被 iptables/nftables 丢弃
→ 用 `iptables -t raw -j TRACE` 或直接看计数器
```

### 排查的四个命令

```bash
ip route get <dst>              # 内核会选哪条路由
ip route show table all         # 所有路由表（含策略路由）
traceroute -n <dst>             # 逐跳看在哪断
ss -rn                          # 路由缓存（部分场景）
```

**"逐跳在哪断"** 比"整体不通"信息量大得多。

### 小结

```
① 路由是"最长前缀匹配"
② 用 ip route get 问内核，别靠猜
③ 双向都要有路由（回程最容易漏）
④ 转发要 ip_forward，出口要 NAT
⑤ 多默认路由看 metric
```
