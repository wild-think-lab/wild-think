### 顺序不能反

```
① 资产清点（有什么、谁负责、在哪）
② 扫描/比对（有哪些漏洞）
③ 排序（先修哪个）
④ 修复（窗口、回滚）
⑤ 验证（真的修好了）
```

**"先买扫描器"** → 扫出一堆 IP，但没人认领。

### 资产清点最小字段

```
IP / 主机名 / 系统版本 / 开放端口 / 业务归属 / 负责人 / 是否对外
```

**"不知道谁负责"** → 漏洞永远挂着。

### 扫描（两种视角）

```bash
# 系统包视角（OS 补丁）
dnf updateinfo list security
# 或
apt list --upgradable 2>/dev/null | grep -i security
```

```
应用视角：依赖漏洞（SCA）、容器镜像扫描、Web 漏洞（DAST）
```

**三者互补**：OS 补丁修不了 Log4j，SCA 也修不了内核漏洞。

### 优先级：不要按"数量"排

```
CVSS 高 + 可远程利用 + 对外暴露  → 立即
CVSS 高 + 仅内网 + 需认证       → 本周
CVSS 中 + 无利用条件            → 计划窗口
无修复方案                      → 缓解（隔离/关闭端口/WAF）
```

**"按 CVSS 排序"** 会先修一堆不可利用的，漏掉真正危险的。

### 补丁窗口与回滚

```
① 先测试环境验证（关键业务）
② 生产分批（先小流量/非核心）
③ 有回滚方案（快照/包版本保留）
④ 有验证（版本号、服务状态、关键接口）
```

```bash
# 只更新安全补丁，保留升级历史
dnf update --security -y
rpm -qa --last | head
```

### 验证（最容易漏）

```bash
# 修完再扫一次，确认该 CVE 不再命中
# 或至少确认包版本 >= 修复版本
dnf info <pkg> | grep -i version
```

**"更新完就宣布修好"** → 重启后旧内核仍在跑（内核补丁必须重启）。

### 五个"扫了也修不完"

**① 没有资产清单**

```
扫描器扫到幽灵 IP，真实资产没覆盖
```

**② 没有 owner**

```
工单派不出去，谁也不认
```

**③ 优先级错**

```
先修不可利用的，真实风险一直在
```

**④ 修了没重启**

```
内核/glibc 补丁未生效
```

**⑤ 没有例外流程**

```
业务方口头说"不能停" → 漏洞永久挂着
```

**例外要有**：书面风险接受 + 到期时间 + 缓解措施。

### 检查清单

```
□ 资产清单完整（含负责人）
□ 三种扫描视角都有（OS/SCA/DAST）
□ 优先级按"可利用性 + 暴露面"
□ 有测试环境验证
□ 生产分批 + 可回滚
□ 修复后有验证（版本/扫描）
□ 内核补丁已重启确认
□ 有例外审批与到期复查
□ 有 SLA（高危 7 天/中危 30 天）
□ 有月度趋势（未修复数下降）
```
