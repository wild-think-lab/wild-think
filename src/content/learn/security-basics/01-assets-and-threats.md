### 先做资产盘点

安全工作的第一步不是买设备，是**写下你有什么**：

```
① 数据：客户信息、订单、合同、源码
② 系统：对外网站、内网系统、数据库、堡垒机
③ 账号：管理员账号、第三方 API key、证书私钥
④ 网络：公网 IP、VPN、专线
⑤ 人员：谁能接触生产、谁能改配置
```

**没盘过的资产，等于没保护**。

### 三个问题定优先级

```
① 丢了什么最疼？（数据 > 系统 > 设备）
② 谁会惦记？（外部扫描 > 内部误操作 > 离职人员）
③ 最坏会怎样？（业务中断 / 罚款 / 声誉 / 法律责任）
```

回答完之后，优先级通常是这样：

```
高：公网暴露的管理端口、弱口令、能直接拿到数据库的路径
中：内部横向移动、日志缺失、无备份
低：很少用的旧系统（但要隔离）
```

### 威胁建模：一张表就够

| 资产 | 威胁 | 可能性 | 影响 | 现有措施 | 缺口 |
| --- | --- | --- | --- | --- | --- |
| 客户数据库 | 未授权访问 | 高 | 极高 | 仅内网 | 无审计、无脱敏 |
| 堡垒机 | 弱口令 | 中 | 高 | 密码登录 | 未强制 MFA |
| 官网 | 注入 | 高 | 中 | WAF | 未做代码扫描 |
| 源码仓 | 泄露 key | 中 | 高 | 私有仓 | 无 secret 扫描 |

**这张表就是你的年度安全计划**：缺口列就是待办。

### 一个真实的教训

某公司安全预算都花在"边界防火墙 + IPS"，结果被入侵的路径是：

```
一个开发把生产数据库的连接串（含密码）提交到了公开的 GitHub 仓库
→ 扫描机器人 5 分钟内发现
→ 攻击者直连数据库（数据库对公网开放 3306）
```

**两个低级问题，绕过了所有边界设备**。

启示：

```
① 内部问题（配置、密钥、账号）往往比外部攻击更致命
② 边界防护不能替代"最小暴露面"
③ 密钥扫描比买设备便宜得多
```

### 安全的四层结构

```
① 身份与访问（谁能进、能做什么）
② 暴露面（对外开了什么）
③ 检测与响应（出了事多久知道）
④ 恢复与合规（能不能回到正常、能不能证明合规）
```

**新手最容易只做②**（买防火墙），而①③④才是长期有效的部分。

### 从哪开始（前 30 天）

```
第 1 周：资产盘点（写清单，标"公网可达"）
第 2 周：暴露面收敛（关掉不必要的公网端口，管理口绑内网）
第 3 周：账号治理（禁弱口令、开 MFA、清理僵尸账号）
第 4 周：补基础检测（登录失败告警、异常外联告警）
```

这四周做的事，比"上一个昂贵的设备"更能降低真实风险。

### 本章要点

```
① 先盘资产，再谈防护
② 优先级来自"影响 × 可能性"，不来自厂商推荐
③ 内部配置问题比外部攻击更常见
④ 四层结构里，身份与访问是第一层
⑤ 前 30 天做四件事：盘点、收敛、账号、检测
```
