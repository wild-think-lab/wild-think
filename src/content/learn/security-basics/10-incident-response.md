### 前 60 分钟的固定顺序

```
0-10 分钟：确认与止损（不急着删）
10-30 分钟：隔离与取证
30-60 分钟：定位入口与范围
之后：清除、加固、复盘
```

**"第一时间重装系统"** → 证据全没了，无法知道怎么进来的。

### 0-10 分钟：先做什么

```
① 确认是真事件（不是误报）：看告警、看业务影响
② 止血：摘流量 / 关入口 / 改密码（不删文件）
③ 拉起应急群：谁决策、谁操作、谁记录
④ 开始记时间线（每条操作带时间戳）
```

**关键**：所有操作前先"记下来在做什么"，事后复盘靠它。

### 10-30 分钟：隔离 + 取证

```bash
# 不关机、不重启（内存里有证据）
# 网络隔离（而不是直接断电）
iptables -I INPUT -j DROP
iptables -I OUTPUT -j DROP

# 保留现场
date; uptime; who; last -20
ps auxf > /tmp/ps.txt
ss -antp > /tmp/ss.txt
crontab -l > /tmp/cron.txt
ls -la /tmp /dev/shm > /tmp/tmp.txt
```

**内存取证**（如有条件）：

```
先 dump 内存，再做其他操作（顺序错了证据就没了）
```

### 30-60 分钟：定位入口

```
① 看 Web 日志异常请求（上传、命令执行、大量 404）
② 看新增账号/密钥（/etc/passwd、authorized_keys）
③ 看定时任务与启动项（crontab、systemd unit）
④ 看外联（异常出站连接、DNS 查询）
⑤ 看文件时间戳（近期被改的系统文件）
```

```bash
find / -xdev -mtime -2 -type f -newer /etc/hostname 2>/dev/null | head -50
grep -r "base64" /etc/cron* 2>/dev/null
```

### 清除与加固

```
① 从可信镜像重建（比"删掉恶意文件"更可靠）
② 全量改密（所有相关账号、密钥、token）
③ 补入口漏洞（否则重建也会再中）
④ 验证：再扫一次 + 观察 24-72 小时
```

**"只删了木马"** → 后门/定时任务还在。

### 五个"越救越乱"

**① 直接重装**

```
入口不明 → 重装后再中一次
```

**② 边救边删日志**

```
无法复盘，也无法举证
```

**③ 多人同时操作**

```
互相覆盖，时间线混乱
```

**④ 不通知业务/客户**

```
合规与信任问题（有法定披露要求）
```

**⑤ 只修这一台**

```
同网段同镜像的其他机器同样中招
```

### 复盘要点

```
① 入口（哪条路径进来的）
② 停留时间（多久才发现）
③ 检测缺口（为什么没告警）
④ 响应缺口（为什么恢复慢）
⑤ 横向影响（还波及了什么）
```

### 检查清单（平时就要准备）

```
□ 有应急联系人名单（含决策人）
□ 有隔离手段（能快速摘流量）
□ 有可信镜像/重装流程
□ 日志集中存储（本地被删仍有副本）
□ 有取证脚本（一键收集现场）
□ 有改密清单（账号/密钥/token）
□ 有对外沟通模板
□ 有复盘模板
□ 演练过至少一次
□ 知道哪些操作会破坏证据
```
