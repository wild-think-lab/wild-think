### 四类洞，占绝大多数

```
① 注入（SQL / 命令 / 模板）
② 认证与授权（弱口令、越权）
③ 敏感信息泄露（接口返回太多、日志带密码）
④ 配置错误（目录遍历、调试接口、CORS）
```

### 注入：永远的参数化

```python
# 错
cur.execute("SELECT * FROM u WHERE name='%s'" % name)

# 对
cur.execute("SELECT * FROM u WHERE name=%s", (name,))
```

```php
// 错：exec 拼接
// 对：参数化 + 白名单
```

**判据**：任何"字符串拼接出 SQL/命令"的地方都是洞。

**命令注入**：

```bash
# 错：system("ping " + host)
# 对：白名单校验 + 参数数组（不经过 shell）
```

### 越权（最常见，扫描器查不到）

```
水平越权：改 order_id 就能看别人的订单
垂直越权：普通用户调到管理接口
```

```python
# 每个资源访问都要校验归属
if order.user_id != current_user.id: abort(403)
```

**"前端隐藏了按钮"** 不是授权，只是看不见。

### 认证与令牌

```
① 密码：加盐慢哈希（bcrypt/argon2），不用 md5/sha1
② 登录限速 + 失败锁定
③ JWT：校验签名、过期、算法白名单（禁 none）
④ 会话：登出即失效（服务端有黑名单）
```

**常见错**：

```
JWT 里放权限但从不校验签名
token 放 localStorage 且无 XSS 防护
```

### 敏感信息泄露

```
① 接口返回整个对象（含 password_hash）
② 报错栈直接给用户
③ 日志打请求体（含密码/身份证）
④ 目录列表开启
```

```nginx
autoindex off;
server_tokens off;
```

**判据**：拿一个普通账号遍历所有接口，看返回字段。

### 配置错误三类

```
① CORS：Access-Control-Allow-Origin: * 且允许凭据
② 调试接口：/actuator、/debug、/swagger 对公网开放
③ 上传：类型/大小/存储位置/可执行
```

### 怎么测（三层）

```
① 静态：代码审查 + 依赖扫描（SCA）
② 动态：认证后的爬虫 + 参数变异（含越权用例）
③ 业务：两个账号互访对方资源（手工必须做）
```

**"只跑扫描器"** 查不到越权与业务逻辑漏洞。

### 五个"修了还是有洞"

**① 只在前端校验**

```
直接调接口就绕过
```

**② 只拦了 GET 没拦 POST**

```
同一逻辑多个入口
```

**③ 越权只在列表页校验**

```
详情/导出/删除接口没校验
```

**④ 上传只校验后缀**

```
改 Content-Type 或双后缀绕过
```

**⑤ 报错信息泄露结构**

```
SQL 报错回显 → 直接看到表名
```

### 检查清单

```
□ 所有 SQL 参数化
□ 命令执行走白名单/参数数组
□ 每个资源访问校验归属
□ 管理接口有角色校验（后端）
□ 密码加盐慢哈希
□ 登录限速与锁定
□ JWT 校验签名/算法/过期
□ 接口返回字段最小化
□ 报错不暴露栈
□ 关闭目录列表与调试端点
□ CORS 白名单（不 * + credentials）
□ 上传校验类型/大小/不可执行
□ 依赖定期扫描
□ 有越权专项测试用例
```
