### 一棵倒着长的树

Linux 只有**一个根**，叫 `/`。所有东西都挂在这棵树上，没有 C 盘 D 盘。插上 U 盘不是"多一个盘"，而是"多一个目录"。

常用目录记住这几个就够干活：

| 目录 | 放什么 | 为什么重要 |
| --- | --- | --- |
| `/etc` | 系统与服务的配置文件 | 改配置基本都在这，`/etc/nginx/nginx.conf` |
| `/var` | 会不断变大的数据，尤其 `/var/log` | 日志在这，排查故障第一站 |
| `/home` | 普通用户的家目录 | 你的文件在这，`/home/你的用户名` |
| `/root` | root 用户的家目录 | 只有 root 能进 |
| `/usr/bin` | 你敲的命令本体 | `ls` 这个命令文件就在这 |
| `/opt` | 手动装的第三方软件 | 源码编译安装常放这 |
| `/tmp` | 临时文件 | 重启可能被清空，别放重要东西 |

### 绝对路径 vs 相对路径

- **绝对路径**：从 `/` 开始，`/var/log/syslog`。在哪执行都指向同一个文件。
- **相对路径**：从当前位置算起，`log/syslog`。当前位置一变，它指向的就变了。

`pwd` 随时告诉你"我现在在哪"：

```bash
pwd                 # /home/wang
cd /var/log         # 切到日志目录，绝对路径
cd ..               # 上一级，相对路径
cd ~                # 回家目录，~ 就是家目录的简写
cd -                # 回上一个待过的地方
```

`cd ..` 里的 `..` 是"上一级"，`.` 是"当前目录"。所以 `./start.sh` 意思是"执行当前目录下的 start.sh"——不写 `./` 时系统只会去 `$PATH` 里找，这就是"命令明明在，却提示 not found"的最常见原因。

### 一切皆文件：设备也是文件

`sda` 是硬盘、`sda1` 是第一块分区，但你在 `/dev` 里看到的是**文件**。想知道磁盘使用情况，不是打开什么管理工具，而是：

```bash
df -h        # 各分区用了多少、还剩多少
lsblk        # 有几块盘、怎么分的
du -sh /var  # 某个目录一共占多大
```

`df -h` 是"磁盘满了"的第一条命令。`-h` 是 human，把字节换成 G/M。

### 通配符和花括号

每次都要敲一长串文件名很蠢，所以有通配符：

```bash
ls /var/log/*.log      # 所有以 .log 结尾的
rm -i /tmp/*.tmp       # 删前一个个确认
cp /etc/nginx/nginx.conf{,.bak}   # 复制一份 .bak 备份，等价于 cp a a.bak
```

通配符是 **Shell 展开的**，不是命令自己处理的。所以 `rm *` 这件事格外危险——第 4 章会说怎么避免。

### 软链接：给路径起别名

```bash
ln -s /opt/app/current /usr/local/bin/app
```

左边是真实文件，右边是快捷方式。软件升级时只改链接指向，调用方路径不用变——线上部署经常这么干。

### 自己验证

```bash
pwd
cd /tmp && pwd          # 确认切换成功了
ls -l /usr/bin/ls       # 看看命令文件本身的属性
df -h | head -5
```

### 本章小结

- 只有一个根 `/`，磁盘、设备都是树上的"文件"。
- 配置在 `/etc`、日志在 `/var/log`、自己在 `/home`、手装的软件在 `/opt`。
- 记住 `pwd`（我在哪）、`cd`（去哪）、`df -h`（还剩多少）。
