### 它要解决的三个问题

```
① 谁能登哪台（授权）
② 登上去做了什么（审计/回放）
③ 高危命令拦住（策略）
```

**"装了 = 审计"** 是误解：没开录像、没命令策略，等于只换了个登录入口。

### 部署（容器，最小可用）

```bash
cd /opt && git clone https://github.com/jumpserver/installer.git
cd installer && ./jmsctl.sh install
./jmsctl.sh start
```

```
组件：core（API/Web）、koko（SSH 代理）、lion（RDP 代理）
依赖：MySQL（或自带）、Redis
```

**要点**：

```
① 443 端口对外，其他组件不要暴露
② 会话录像要存到独立盘/对象存储
③ 数据库和 Redis 要持久化
```

### 资产与账号

```
① 录入资产（IP/端口/协议/系统用户）
② 建"特权账号"（登录目标机用的）
③ 建"系统用户"（堡垒机自身登录目标机用的）
④ 授权规则：谁 + 哪些资产 + 哪些账号
```

**"只录了资产没授权"** → 用户登录后看不到任何主机。

### 命令过滤

```
规则：命令黑名单（rm -rf、shutdown、dd、mkfs）
动作：拒绝 / 二次审批 / 只告警
```

**判据**：过滤的是"字符串"，绕法很多 → 关键操作要靠**审批**而不是关键词。

### 会话回放与日志

```
① 录像文件保留（一般 180 天）
② 命令记录（谁在什么时候执行了什么）
③ 登录日志（失败/成功/来源 IP）
④ 与 SIEM 对接（异常登录告警）
```

```bash
# 看录像存储占用
du -sh /opt/jumpserver/data/media/*
```

**"录像只存本地"** → 堡垒机被拿下，证据一起没了。

### 五个"上了还是查不到"

**① 用户绕过堡垒机直连**

```
安全组/防火墙没限制"只允许堡垒机 IP"
```

**② 录像没开**

```
资产上没启用会话录像
```

**③ 多人共用一个账号**

```
审计到"账号"，审计不到"人"
```

**④ 只审计 SSH 不审计 RDP/数据库**

```
运维从图形界面全绕过
```

**⑤ 高危命令只在告警**

```
出了事才知道，已经删完了
```

### 落地顺序（很重要）

```
① 先收紧网络：目标机只允许堡垒机访问
② 再统一账号：一人一账号
③ 然后开录像 + 命令策略
④ 最后接告警与报表
```

**顺序反了**：先上系统、后收网络 → 大家照旧直连，堡垒机成了摆设。

### 检查清单

```
□ 目标机只允许堡垒机网段访问
□ 一人一账号（不共用）
□ 会话录像开启且异地保存
□ 命令策略（拒绝/审批）
□ 覆盖 SSH + RDP + 数据库协议
□ 登录失败/异地登录有告警
□ 录像保留期符合合规
□ 堡垒机自身高可用（或快速重建）
□ 有周期性审计报表
□ 有绕过直连的检测
```
