## 一、先弄懂它是什么

**堡垒机（跳板机 + 审计）是一条"被强制经过的路"，不是一个"更方便的 SSH 客户端"。**

```
运维人员 → 堡垒机（认证 + 授权 + 录像 + 命令策略）→ 目标主机
                 ↑ 唯一入口，目标机只信它
```

**它解决的问题**：把"谁能登哪台、登上去干了什么"从"靠自觉"变成"靠系统"。没有它，出事后你只能回答"某人可能登过"，无法举证。

### 它和普通跳板机的区别

| 维度 | 普通跳板机 | 堡垒机 |
| --- | --- | --- |
| 认证 | 共享密钥 | 统一账号 + 多因子 |
| 授权 | 全都能登 | 按人/资产/账号细粒度 |
| 审计 | 只有 shell 历史 | 会话录像 + 命令记录 + 文件传输 |
| 拦 截 | 无 | 命令黑名单 / 二次审批 |
| 协议 | SSH | SSH / RDP / 数据库 / Web |

### 关键技术原理

```
① 协议代理：用户连的是堡垒机，堡垒机再和目标机建连（SSH 代理 / RDP 网关）
   → 目标机只允许堡垒机 IP 访问，绕不过去
② 会话录制：把终端输出流（或 RDP 画面帧）落成可回放文件
③ 命令解析：在 SSH 通道里解析用户输入，命中策略就阻断或转审批
④ 统一账号：人在堡垒机上是"人"，在目标机上是"系统账号"，两者解耦
```

**注意**：命令解析靠字符串匹配，`cat > x`、base64、脚本执行都能绕过。所以真正的安全边界是"审批 + 最小权限"，不是关键词表。

### 五个必须知道的局限

```
① 只代理 SSH 不管 RDP/数据库 → 运维从别的协议全绕过
② 录像只存本地 → 堡垒机被入侵，证据一起没了
③ 多人共用一个账号 → 审计到"账号"，审计不到"人"
④ 网络没收紧 → 大家照旧直连，系统成摆设
⑤ 策略只在告警 → 出事才知道，已经删完了
```

### 落地顺序（顺序错了等于白上）

```
① 先收网络：目标机安全组只允许堡垒机网段
② 再统一账号：一人一账号，禁共享
③ 然后开录像 + 命令策略
④ 最后接告警、报表、合规审计
```

### 它要解决的三个问题

```
① 谁能登哪台（授权）
② 登上去做了什么（审计/回放）
③ 高危命令拦住（策略）
```

**"装了 = 审计"** 是误解：没开录像、没命令策略，等于只换了个登录入口。

### 部署（容器，最小可用）

```bash
cd /opt && git clone https://github.com/jumpserver/installer.git
cd installer && ./jmsctl.sh install
./jmsctl.sh start
```

```
组件：core（API/Web）、koko（SSH 代理）、lion（RDP 代理）
依赖：MySQL（或自带）、Redis
```

**要点**：

```
① 443 端口对外，其他组件不要暴露
② 会话录像要存到独立盘/对象存储
③ 数据库和 Redis 要持久化
```

### 资产与账号

```
① 录入资产（IP/端口/协议/系统用户）
② 建"特权账号"（登录目标机用的）
③ 建"系统用户"（堡垒机自身登录目标机用的）
④ 授权规则：谁 + 哪些资产 + 哪些账号
```

**"只录了资产没授权"** → 用户登录后看不到任何主机。

### 命令过滤

```
规则：命令黑名单（rm -rf、shutdown、dd、mkfs）
动作：拒绝 / 二次审批 / 只告警
```

**判据**：过滤的是"字符串"，绕法很多 → 关键操作要靠**审批**而不是关键词。

### 会话回放与日志

```
① 录像文件保留（一般 180 天）
② 命令记录（谁在什么时候执行了什么）
③ 登录日志（失败/成功/来源 IP）
④ 与 SIEM 对接（异常登录告警）
```

```bash
# 看录像存储占用
du -sh /opt/jumpserver/data/media/*
```

**"录像只存本地"** → 堡垒机被拿下，证据一起没了。

### 五个"上了还是查不到"

**① 用户绕过堡垒机直连**

```
安全组/防火墙没限制"只允许堡垒机 IP"
```

**② 录像没开**

```
资产上没启用会话录像
```

**③ 多人共用一个账号**

```
审计到"账号"，审计不到"人"
```

**④ 只审计 SSH 不审计 RDP/数据库**

```
运维从图形界面全绕过
```

**⑤ 高危命令只在告警**

```
出了事才知道，已经删完了
```

### 落地顺序（很重要）

```
① 先收紧网络：目标机只允许堡垒机访问
② 再统一账号：一人一账号
③ 然后开录像 + 命令策略
④ 最后接告警与报表
```

**顺序反了**：先上系统、后收网络 → 大家照旧直连，堡垒机成了摆设。

### 检查清单

```
□ 目标机只允许堡垒机网段访问
□ 一人一账号（不共用）
□ 会话录像开启且异地保存
□ 命令策略（拒绝/审批）
□ 覆盖 SSH + RDP + 数据库协议
□ 登录失败/异地登录有告警
□ 录像保留期符合合规
□ 堡垒机自身高可用（或快速重建）
□ 有周期性审计报表
□ 有绕过直连的检测
```
