如果你完全没接触过这行，先把一句话记住：

> **网站不是"一个文件"，是一台一直开着的机器上，一个一直跑着的程序。**

这篇文章不教你敲命令，只负责把这件事讲明白。看完你会知道"装环境""配端口""解析域名"分别是在解决什么问题。

## 一、把一台服务器拆成五层

| 层 | 通俗说法 | 常见东西 | 坏了会怎样 |
| --- | --- | --- | --- |
| 1 硬件 | 一台不会关机的电脑 | CPU、内存、硬盘、网卡 | 机器起不来、卡顿 |
| 2 操作系统 | 管硬件的总管 | Linux（CentOS / Ubuntu） | 登录不进去 |
| 3 服务程序 | 真正干活的软件 | Nginx、Apache、MySQL、PHP | 页面报错、连不上数据库 |
| 4 网络 | 让外面的人找到它 | IP、端口、防火墙、安全组 | 自己电脑能开，别人打不开 |
| 5 名字 | 给人记的名字 | 域名、DNS | 域名打不开但 IP 能开 |

**新手 90% 的困惑，都是把层搞混了。** 比如"网站打不开"可能是第 4 层（安全组没放行），也可能是第 3 层（服务没启动）——不动手分层验证，就只能靠猜。

## 二、敲下回车之后，发生了什么

假设你在浏览器里输入 `http://203.0.113.10` 并按回车，接下来的顺序是这样的：

1. **浏览器**：解析 URL，知道要访问 `203.0.113.10` 的 80 端口。
2. **网络**：先发 TCP 三次握手，建立一条连接（能不能连上，看第 4 层）。
3. **操作系统**：把连接交给"正在监听 80 端口"的那个程序。
4. **服务程序（Nginx）**：收到请求，决定返回什么文件或转给谁处理。
5. **浏览器**：拿到 HTML，解析、下载 CSS/JS/图片、渲染出画面。

这里有个关键概念——**端口**。一台机器可以同时跑很多程序，IP 只能定位"哪台机器"，端口定位"哪个程序"。所以：

```text
IP   203.0.113.10   → 哪台机器
端口 80            → 机器上的哪个程序（80 = HTTP，443 = HTTPS）
```

**没有程序监听那个端口，请求就一定失败。** 这是"网站打不开"的第一检查点。

## 三、为什么要专门装一个"Web 服务软件"

你可能会问：机器上放个 HTML 文件，浏览器直接读不行吗？

不行。因为浏览器不会去读别人硬盘上的文件，它只会**通过网络发 HTTP 请求**。必须有程序替你做这几件事：

- 监听端口，等请求进来；
- 把 URL 映射到硬盘上的具体文件（比如 `/` → `index.html`）；
- 返回正确的响应头（状态码、内容类型、缓存策略）；
- 处理并发（同一秒来 100 个请求）；
- 记录日志（出事时唯一的证据）。

这就是 **Nginx / Apache** 的职责。它们不做业务，只负责"接客"。

同样，**MySQL** 负责存数据（用户、文章、订单），**PHP / Python / Node** 负责写业务逻辑（"查这个用户的订单，拼成页面"）。

四个东西合起来，就是常说的 LAMP / LNMP：

```text
Linux（系统） + Nginx/Apache（接客） + MySQL（存数据） + PHP（算逻辑）
```

## 四、第一次动手：让这台机器"能被人访问"

你需要的只是一台 Linux 机器：云厂商最低配（1 核 2G）就够，或者本地用 VMware/VirtualBox 装一台虚拟机。

### 步骤 1：登录

云主机一般在控制台给一个公网 IP 和初始密码；虚拟机装完直接在本机窗口里操作。

```bash
# 在你自己的电脑上（Windows 自带 ssh，或 Xshell/PuTTY）
ssh root@203.0.113.10
```

看到提示符变成 `[root@xxx ~]#` 就说明登录成功了。

### 步骤 2：装 Web 服务

```bash
# Ubuntu / Debian
apt update && apt install -y nginx

# CentOS 7 / Rocky / Alma
yum install -y nginx        # CentOS 7 默认源里没有，需要先装 EPEL：yum install -y epel-release
dnf install -y nginx        # Rocky / Alma / CentOS 8+

# 启动并设为开机自启
systemctl start nginx
systemctl enable nginx
```

### 步骤 3：确认它在工作

```bash
systemctl status nginx           # 看到 active (running)
ss -lntp | grep :80              # 看到 nginx 在监听 80
curl -I http://127.0.0.1         # 返回 HTTP/1.1 200 OK
```

### 步骤 4：从外面访问

在自己电脑的浏览器里输入 `http://你的公网IP`，看到 Nginx 欢迎页就算成功。

> 云服务器如果打不开，先去控制台的**安全组**放行 80 端口——这是第 4 层的问题，不是 Nginx 的问题。

## 五、卡住了对照这张表

| 现象 | 最可能的原因 | 怎么确认 |
| --- | --- | --- |
| `curl 127.0.0.1` 就失败 | 服务没启动 | `systemctl status nginx` |
| 本机能开、外面打不开 | 安全组 / 防火墙没放行 | `firewall-cmd --list-all`；开 80 |
| 打开是"无法访问此网站" | 端口没在监听 | `ss -lntp` 里看不到 80 |
| 打开是别的东西 | 有多个程序抢 80 | `ss -lntp` 看 PID，停掉冲突的 |
| 打开是 403 Forbidden | 文件权限/目录索引 | 看 `/var/log/nginx/error.log` |

**排错顺序永远是：服务在跑吗 → 端口在听吗 → 本机能通吗 → 外面能通吗。** 四步走完，问题一定落在其中一层。

## 六、到这里你已经懂了什么

- 网站 = 机器 + 系统 + 服务程序 + 网络 + 域名，五层各管一件事；
- IP 定位机器，端口定位程序；
- Nginx 只负责"接客"，不算业务；
- 排查要分层，不要靠猜。
