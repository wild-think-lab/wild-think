新手最容易卡在"我的网页在服务器上明明能打开，为什么别人打不开"。这篇文章只解决这一类问题。

## 一、IP：谁在找谁

IP 地址就是网络里的门牌号，让数据知道该送到哪台机器。

```bash
# 看自己这台机器的地址
ip -br a            # Linux
ipconfig            # Windows
```

会看到两类地址：

| 类型 | 长相 | 谁在用 |
| --- | --- | --- |
| 内网 IP | `192.168.x.x`、`10.x.x.x`、`172.16~31.x.x` | 家里/公司/机房内部的机器互访 |
| 公网 IP | 其他（如 `203.0.113.10`） | 全世界都能访问到的地址 |

三个必须记住的"本地地址"：

```text
127.0.0.1    本机回环，永远只指自己
0.0.0.0      监听"所有网卡"，对外表示"任何来源都能连"
localhost    一个名字，通常解析成 127.0.0.1
```

> 一个高频 bug：服务监听 `127.0.0.1:8080`，本机 `curl` 通，别人永远连不上。因为它只接受来自本机的连接。要让外面能连，必须监听 `0.0.0.0`。

## 二、端口：找哪个门

IP 定位机器，端口定位机器上的程序。同一台机器可以同时当网站、数据库、SSH 登录入口，靠的就是端口不同。

| 端口 | 通常是谁 | 说明 |
| --- | --- | --- |
| 22 | SSH | 远程登录 |
| 80 | HTTP | 明文网页 |
| 443 | HTTPS | 加密网页 |
| 3306 | MySQL | 数据库 |
| 6379 | Redis | 缓存 |
| 8080 / 3000 | 自建应用 | 习惯用法，可改 |

查"谁在监听"：

```bash
ss -lntp
# -l 只听着的  -n 显示数字端口  -t TCP  -p 显示进程
```

输出里 `0.0.0.0:80` 与 `127.0.0.1:80` 是完全不同的含义，看地址那一列比看端口更重要。

三个端口相关的常识：

1. **1024 以下需要 root**（或 `CAP_NET_BIND_SERVICE`），所以普通用户跑的程序常用 8080；
2. **端口被占用**报 `Address already in use`，用 `ss -lntp` 找 PID 再处理；
3. **云服务器有安全组**，机器上开着端口 ≠ 外网能连，两层都要放行。

## 三、域名：怎么记住名字

IP 难记，于是有了域名。域名到 IP 的翻译由 DNS 完成。

```bash
dig example.com +short       # 查 A 记录（域名 → IPv4）
dig example.com AAAA +short  # 查 IPv6
nslookup example.com         # Windows 也能用
```

一次解析要走：本机缓存 → 本地 DNS → 递归服务器 → 权威服务器。所以"域名解析没生效"通常是**缓存还没过期**（等 TTL）或**记录没配对**（A 记录写错 IP）。

新手要配的只有两类记录：

| 记录 | 作用 | 例子 |
| --- | --- | --- |
| A | 域名 → IPv4 | `blog.example.com → 203.0.113.10` |
| CNAME | 域名 → 另一个域名 | `www.example.com → blog.example.com` |

配好后用 `dig` 验证，**别用浏览器验证**——浏览器有缓存，还会自动跳 HTTPS，看到的未必是真实解析结果。

## 四、HTTP：进门之后说什么

TCP 连上之后，浏览器发一段文本，服务器回一段文本。就这么简单。

```http
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
```

服务器回：

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 132

<h1>hello</h1>
```

关键在**状态码**，它告诉你问题出在哪一层：

| 状态码 | 含义 | 谁的锅 |
| --- | --- | --- |
| 200 | 正常 | — |
| 301 / 302 | 跳转 | 配置了重定向 |
| 403 | 拒绝访问 | 权限或目录索引被禁 |
| 404 | 找不到 | URL 与文件对不上 |
| 500 | 服务内部报错 | 应用代码/依赖 |
| 502 / 504 | 网关拿不到后端 | 反向代理后面的服务挂了/超时 |

`502` 是最容易被误解的一个：它不代表"网站挂了"，而是**"门口的服务活着，但里面的服务没响应"**。

## 五、动手：用 curl 看清一次完整请求

`curl` 是命令行里的浏览器，最适合做验证。

```bash
# 只看响应头，不看正文
curl -I http://203.0.113.10

# 看完整过程：DNS、连接、TLS、请求、响应
curl -v http://203.0.113.10 2>&1 | head -40

# 只看状态码
curl -o /dev/null -s -w "%{http_code}\n" http://203.0.113.10

# 指定 Host 头（测虚拟主机/域名绑定，不用改 DNS）
curl -H "Host: blog.example.com" http://203.0.113.10
```

第四条是排查"域名没解析好但想先验证服务器配置"的利器。

## 六、一张图记住排查顺序

```text
域名能解析吗？      dig 域名 +short        → 空 = DNS 问题
IP 通吗？          ping IP                → 不通 = 网络/安全组
端口开吗？          telnet IP 端口 或 nc -zv IP 端口 → 不通 = 服务没起/防火墙
HTTP 回什么？       curl -I URL            → 状态码说明问题在哪层
内容对不对？        curl -v URL            → 看响应体与跳转
```

按顺序走，每一步只回答一个问题。**跳过任何一步，后面都会白查。**

## 七、新手三个高频误区

1. **"ping 通就是服务正常"** —— 完全无关。ping 走 ICMP，网页走 TCP+HTTP，两条路可以一条通一条不通。
2. **"域名解析了就能访问"** —— 还要端口放行、服务在跑、`server_name` 配对。
3. **"改完 DNS 立刻生效"** —— 受 TTL 限制，也可能被本机或运营商缓存拖住。

> 一句经验：**网络问题按"名字 → 地址 → 端口 → 协议 → 内容"五级往下查**，每一级都有对应的命令。只要顺序不乱，就不会出现"查了两小时发现是安全组"这种事故。
