### 前提：只扫自己有权限的资产

```
扫别人的 IP = 违法行为（即使"只是看看"）
→ 只扫自有/书面授权的目标
```

**"扫公网随便一个段"** 是绝对不能做的事。

### nmap 六种常用扫描

```bash
# 1) 快速（常用端口）
nmap -sT --top-ports 100 10.0.0.5

# 2) 全端口 TCP（慢但完整）
nmap -sS -p- --min-rate 1000 10.0.0.5

# 3) 服务与版本
nmap -sV -p 22,80,443 10.0.0.5

# 4) 默认脚本（基础探测）
nmap -sC -sV 10.0.0.5

# 5) UDP（很慢，只扫关键端口）
nmap -sU -p 53,123,161 10.0.0.5

# 6) 网段存活
nmap -sn 10.0.0.0/24
```

**`-sS`（半开）** 需要 root；`-sT` 走完整握手（无需 root，但更容易被日志记录）。

### 判读：state 的三种值

```
open           ：端口开放且有服务
closed         ：端口开放但无服务（会回 RST）
filtered       ：无响应（防火墙 DROP）
```

**"filtered"** 说明"有设备在丢包"（不是"没开"）。

**"closed 变 filtered"** → 中间有防火墙策略变化。

### 结果的实用判读

| 端口 | 服务 | 风险 |
| --- | --- | --- |
| 22 | SSH | 暴露公网 + 密码登录 = 高危 |
| 3306 | MySQL | 暴露公网 = 高危 |
| 6379 | Redis | 未鉴权 = 直接 RCE |
| 9200 | Elasticsearch | 默认无认证 = 数据泄露 |
| 2375 | Docker API | 未 TLS = 直接控主机 |
| 8080/8081 | 管理后台 | 弱口令/未鉴权 |
| 445 | SMB | 勒索最爱 |

**"开着的 2375"** = 等于把主机 root 权限挂在公网。

### 六个"必须排查"的端口

```bash
nmap -sV -p 22,2375,2376,3306,5432,6379,9200,11211,27017 10.0.0.5
```

```
22 SSH / 2375 Docker / 3306 MySQL / 5432 PG
6379 Redis / 9200 ES / 11211 Memcached / 27017 Mongo
```

**"这几个暴露在公网"** = 立刻处理（不是"以后再说"）。

### 五个"扫出来的结果看不懂"

**① 扫到"大量 open"但业务只有 1 个服务**

```
可能是"中间设备/NAT 把所有端口都回"（不是真开放）
→ 用 -sV 看版本号，或从外部多角度验证
```

**② 只扫了 TCP，漏了 UDP**

```
DNS/SNMP/NTP 是 UDP → TCP 扫不到
```

**③ 被 IDS/防火墙干扰**

```
扫描被限速/封禁 → 结果是"filtered"而非真实状态
```

**④ 网段搞错**

```
扫了 10.0.0.0/24，但实际资产在 10.0.1.0/24
```

**⑤ 只扫了"现在"，没扫"历史"**

```
资产是动态的（临时实例/新开端口）
→ 需要"定期扫描 + 变更对比"
```

### 一个"资产自查"流程

```
1) 从云控制台/CMDB 导出"应有的资产清单"
2) 用 nmap -sn 扫存活（发现"清单外"的机器）
3) 对每台扫 top 1000 端口
4) 对比"应有端口"与"实际端口"
5) 差异项：确认为什么开、能否关闭
6) 每季度重跑一次
```

**"清单外的主机"** 往往比"开着的端口"更危险。

### 检查清单

```
□ 只扫授权资产
□ 有"应有资产"清单（CMDB/云控制台）
□ 存活扫描发现清单外主机
□ 全端口扫描（不只 top 100）
□ 服务版本识别（-sV）
□ 高危端口重点排查（22/2375/3306/6379/9200）
□ 关注 UDP 关键端口
□ 结果对比"应有 vs 实际"
□ 每季度重扫
□ 差异项有处理记录
```
