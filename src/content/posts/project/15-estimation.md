### 先说一个事实

```
所有"精确到天"的估算都是假的
但"给出区间 + 说明不确定性"是专业的
```

**"三天"和"三周"的差距，通常不是能力问题，是估算方法问题**。

### 三种估算方法

**① 类比估算（最快，最粗）**

```
"上次那个类似功能用了 5 天" → 这次估 5–7 天
```

**适合**：有可类比的历史。

**② 分解估算（最常用）**

```
把任务拆到"半天以内"的子项，逐项估，再相加
```

**关键**：

```
拆到"能说清做什么"的粒度（半天）
拆不到半天 → 说明还没想清楚
```

**③ 三点估算（PERT，带不确定性）**

```
乐观 O / 最可能 M / 悲观 P
期望 = (O + 4M + P) / 6
```

**适合**：不确定性大的任务（新技术、新领域）。

### 为什么"三天变三周"

**五个系统性原因**：

**① 只估了"写代码"**

```
写代码 1 天
+ 写测试 0.5 天
+ 联调 1 天
+ review 与修改 0.5 天
+ 部署与验证 0.5 天
+ 意外（依赖不可用、需求澄清）1 天
= 5 天
```

**"只估编码时间"是最常见的失真**。

**② 忽略了"等待"**

```
等 review、等测试环境、等外部接口、等排期
→ 这些是"日历时间"，不是"工时"
```

**③ 忽略了"上下文切换"**

```
一个人同时做 3 个任务 → 每个任务的"有效工时"减半
```

**④ 需求未澄清**

```
"做个导出功能" → 导出什么格式？多大？并发？权限？
每条不清楚的地方都是一次"停下来去问"
```

**⑤ 乐观偏差（人性）**

```
所有人都倾向于"这次应该顺利"
→ 历史数据是纠正它的唯一方法
```

### 拆分到"半天粒度"的实操

```
任务：用户导出订单功能
拆：
① 定义导出格式与字段（0.5 天，含与产品确认）
② 后端查询与分页（0.5 天）
③ 生成 CSV/Excel（0.5 天）
④ 异步任务（大文件，0.5 天）
⑤ 下载链接与权限（0.5 天）
⑥ 前端入口与进度（0.5 天）
⑦ 测试与联调（1 天）
⑧ 部署与验证（0.5 天）
= 4.5 天（+ 缓冲）
```

**"拆完发现比原来估的多"是正常的**（原来的估算漏了 5 项）。

### 缓冲怎么留

**两种做法**：

```
① 任务级缓冲（每个任务 +30%）→ 容易被"消耗掉"（学生综合征）
② 项目级缓冲（总工时 +20%，集中管理）→ 更有效
```

**推荐项目级缓冲**：

```
总估算 × 1.2 作为"承诺时间"
超出时从缓冲里扣（有据可查）
```

**"缓冲不公开" vs "公开"**：

```
公开缓冲 → 容易被"提前用完"
不公开 → 团队不知道目标，容易拖
→ 折中：公开"承诺时间"，内部管理缓冲
```

### 一个"可对照"的估算表

| 任务类型 | 常见耗时 | 常被漏掉 |
| --- | --- | --- |
| 新增一个接口 | 0.5–1 天 | 权限、错误码、文档 |
| 改一个已有接口 | 1–2 天 | 兼容旧客户端、回归 |
| 新增一个页面 | 1–2 天 | 空态、错误态、移动端 |
| 数据库加字段 | 0.5 天 | 迁移脚本、回滚方案、索引 |
| 接入第三方 | 1–3 天 | 联调、异常、限流 |
| 修一个 Bug | 0.5–2 天 | 复现环境、根因、回归 |

**"改已有接口"往往比"新增"更贵**（兼容成本）。

### 五个让估算失真的系统性原因

**① 没有历史数据**

```
每次都"凭感觉" → 永远不准
→ 记录"估算 vs 实际"（哪怕只记 10 个任务，也能看出偏差系数）
```

**② 估算者不是执行者**

```
主管估 3 天，实际执行的人知道要 7 天
→ 必须由执行者估
```

**③ 需求变更不算成本**

```
"顺便加个小功能" → 每次都是 0.5–2 天
→ 变更要走"重新估"流程
```

**④ 把"工时"当"日历时间"**

```
5 人天 ≠ 5 天（如果只有 1 人）
且要考虑请假、会议、其他任务
```

**⑤ 没有"不确定性"的表达**

```
"3 天" → 应该改成"2–5 天，取决于 XX 是否能按时提供"
```

**"说清不确定性"是专业度的体现**。

### 一个"估算输出"的模板

```
任务：订单导出
估算：3–5 天（不含等待）
关键假设：
  - 导出格式由产品在本周内确认
  - 数据量 < 100 万行（超出需另评估）
风险：
  - 若需要 Excel 复杂格式，+2 天
  - 若需要异步队列，+1 天
```

**"假设 + 风险"比"一个数字"更有价值**。

### 检查清单

```
□ 估算由执行者做
□ 拆到半天粒度
□ 包含测试/联调/部署/文档
□ 区分"工时"与"日历时间"
□ 表达区间 + 关键假设
□ 列出风险与"如果…则 +N 天"
□ 用项目级缓冲（不是任务级）
□ 记录"估算 vs 实际"并复盘偏差
□ 需求变更重新估算
□ 不承诺"精确日期"（承诺区间 + 检查点）
```
