### 交付延期从来不是"开发慢"

真正常见的四个原因：

1. **需求在过程中变了**，但工期没重估。
2. **环境/依赖没到位**（等客户开防火墙、等硬件到货）。
3. **验收标准没提前对齐**，交付时才发现"这不是我要的"。
4. **没人对"完成"负责**（开发说做完了，测试说没测过，客户说没验收）。

七个关卡的作用就是**把这些前置暴露**。

### 七个关卡

```
① 需求确认     → 出《需求说明》，客户签字
② 方案设计     → 出《技术方案》，内部评审
③ 环境准备     → 环境清单逐项打勾，客户配合确认
④ 开发实施     → 每周进度同步，变更走变更单
⑤ 内部测试     → 测试用例 + 缺陷闭环，出测试报告
⑥ 客户验收     → 按《验收标准》逐项确认，签字
⑦ 上线与移交   → 部署、培训、文档移交、进入维保
```

每关都有**门禁（Gate）**：不通过不进下一关。

### ① 需求确认

最小产出：

```
《需求说明》：做什么、不做什么、验收怎么算
《范围边界》：明确排除项（避免后期"这也顺便做一下"）
```

关键动作：**把"不做什么"写清楚**。交付纠纷 80% 来自"以为包含"。

### ② 方案设计

最小产出：

```
架构图（组件 + 网络 + 数据流）
部署拓扑（几台机器、什么规格）
关键技术选择与理由
风险清单（哪些点可能出问题、怎么兜底）
```

内部评审要有人问："这个方案最坏情况是什么？"

### ③ 环境准备

用清单逐项打勾，别用"我以为"：

```
□ 服务器/虚拟机到位（IP、规格、系统版本）
□ 网络放通（源→目的→端口，逐条确认）
□ 域名与证书
□ 数据库/中间件账号
□ 第三方接口的 key / 白名单
□ 客户侧的对接人（姓名 + 电话 + 职责）
```

**这一步最容易拖**：客户的安全审批可能要两周。要尽早提出，且每周跟进。

### ④ 开发实施

- 每周一次进度同步（发了什么、下周做什么、有什么阻塞）。
- 变更走变更单：**任何需求变更必须评估工期影响**，客户确认后才做。
- 阻塞项当天上报，不要憋到周末。

### ⑤ 内部测试

最小产出：

```
测试用例（覆盖主流程 + 异常流程）
缺陷列表（严重/一般/建议，闭环率 100% 才交付）
测试报告（环境、范围、结论、遗留问题）
```

**遗留问题要写清楚**："已知问题 3 个，不影响验收，计划维保期内修复"。

### ⑥ 客户验收

关键是**提前给验收标准**，且标准可执行：

```
差的标准：系统运行稳定、界面友好
好的标准：
  1. 连续 7 天无 P1 故障
  2. 关键流程 20 个用例全部通过
  3. 首页加载 < 2s（内网）
  4. 数据迁移核对一致（抽样 1000 条，差异 0）
```

验收会现场逐项过，每项给"通过/不通过/待定"，签字。

### ⑦ 上线与移交

```
□ 部署完成并验证
□ 运维文档（怎么启停、怎么看日志、常见故障）
□ 培训（客户运维人员，至少一次，留录像）
□ 账号与权限移交清单
□ 维保范围与响应时效（SLA）
□ 回款节点确认
```

**没有培训与文档的交付，等于把运维责任留给自己**。

### 文档最小集

| 文档 | 谁看 | 什么时候要 |
| --- | --- | --- |
| 需求说明 | 双方 | ① |
| 技术方案 | 内部 + 客户技术 | ② |
| 环境清单 | 双方 | ③ |
| 测试报告 | 客户 | ⑤ |
| 验收报告 | 双方 | ⑥ |
| 部署与运维手册 | 客户运维 | ⑦ |
| 培训材料 | 客户 | ⑦ |

七份文档，缺一份后期就要补三倍时间。

### 一次交付失败的事后复盘

现象：项目延期 3 周，验收时客户提出 12 项"没做到"。

复盘结论：

1. 需求阶段没写"不做什么"，客户认为"数据大屏"包含在范围内（实际报价不含）。
2. 环境准备拖了 10 天（客户防火墙审批），但工期没顺延。
3. 验收标准只有一句"满足需求"，没有可执行项。
4. 中期没有书面进度同步，客户对进度无感知。

改进：

- 需求说明模板加"明确排除项"章节。
- 环境清单作为工期起算的前置条件（未到位则工期顺延）。
- 验收标准必须可量化，随需求说明一起签字。

### 检查清单（项目启动时对照）

```
□ 需求说明含"不做什么"
□ 验收标准可量化，已客户确认
□ 环境清单已发出，有跟进节奏
□ 每周进度同步有记录
□ 变更走单，工期重估
□ 七份文档责任到人
□ 回款节点与验收节点对齐
```
