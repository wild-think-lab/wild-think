### 五层，按影响从大到小

```
① 分块（chunking）—— 影响最大，最常被忽略
② embedding 模型
③ 索引与检索参数
④ 混合检索（关键词 + 向量）
⑤ 重排（rerank）
```

**"换了更大的模型没改善"** → 通常是①的问题。

### ① 分块：最常见的元凶

```
太大（2000 字）→ 语义被稀释，检索命中但回答不准
太小（100 字）→ 上下文不完整
```

**实践建议**：

```
① 按"结构"切（标题/段落/表格行）
② 目标 300–800 tokens（视内容类型）
③ 加重叠（10–20%）保留上下文
④ 每个 chunk 带"来源/标题/路径"元数据
```

**"按固定 512 字切"** 会把一个表格切成两半（语义断裂）。

**带元数据的好处**：

```
检索时能按"文档类型/时间/部门"过滤
回答时能给出引用来源
```

### ② embedding 模型

```
① 语言匹配（中文内容用中文强的模型）
② 领域匹配（代码/医学/AI 语料各有偏好）
③ 维度与成本（维度高精度好但存储/检索贵）
```

**"用英文模型检索中文"** 是最常见的精度损失。

**评估方式**：

```
造 50 条"问题 → 正确 chunk"的样本
→ 算 recall@5 / MRR
→ 换模型前后对比
```

**"没有评估集"** 就没法判断"是否变好了"。

### ③ 索引类型与参数

| 索引 | 特点 |
| --- | --- |
| Flat | 精确，暴力搜索（小数据量） |
| IVF | 聚类分桶，快但需调 nprobe |
| HNSW | 图索引，快且准，内存占用高 |
| PQ/量化 | 压缩，省内存，精度略降 |

**参数要点**：

```
HNSW：M（连接数，16–48）、efConstruction（构建精度）、efSearch（查询精度）
IVF ：nlist（桶数）、nprobe（查几个桶，越大越准越慢）
```

**"召回突然变差"** → 检查 efSearch 是否被调小（为了降延迟）。

### ④ 混合检索

```
向量检索擅长"语义相似"
关键词（BM25）擅长"精确词/编号/人名"
→ 两者互补，用 RRF 或加权融合
```

**"用户搜'ERR_4032'"** → 纯向量检索会很差（编号没有语义）。

**融合方式**：

```python
score = 0.7 * vector_score + 0.3 * bm25_score
# 或 RRF: 1/(k + rank)
```

### ⑤ 重排（rerank）

```
第一阶段（召回）：向量/关键词 → 取 top 50
第二阶段（重排）：cross-encoder 精排 → 取 top 5
```

**"召回里有对的但排不进前 5"** → 这就是 rerank 的价值。

**成本**：

```
rerank 比向量检索慢一个数量级
→ 只对 top 30–50 做
```

### 五个"换了模型还是不准"

**① 分块把语义切碎**

```
换模型解决不了"检索到的 chunk 本身不完整"
```

**② 问题与文档"语言风格"差异大**

```
用户问"怎么报销"，文档写"费用核销流程"
→ embedding 未必能跨过这个鸿沟（需要 query 改写/同义词扩展）
```

**③ 元数据没用于过滤**

```
检索到"3 年前的旧政策" → 明明有新版
→ 应加时间/状态过滤
```

**④ 评估集有问题**

```
评估集本身标注错了 / 只覆盖简单问题
→ "指标很好但用户不满意"
```

**⑤ 数据质量问题**

```
文档里有大量重复/过期/冲突内容
→ 检索到"错误的那一份"
```

**"先治理数据，再调模型"**。

### 一个"调优顺序"

```
1) 建评估集（50–100 条真实问题）
2) 先改分块（结构 + 元数据 + 重叠）
3) 再换/对比 embedding（用 recall@k 判定）
4) 加混合检索（关键词补语义）
5) 加 rerank（提升 top-k 精度）
6) 最后调索引参数（延迟 vs 精度）
```

**"从 ① 开始，别从 ⑥ 开始"**。

### 检查清单

```
□ 有评估集（真实问题 + 正确 chunk）
□ 分块按结构、带重叠、带元数据
□ embedding 语言/领域匹配
□ 索引参数与延迟权衡明确
□ 混合检索（向量 + 关键词）
□ rerank 只对 top-k
□ 元数据可用于过滤（时间/类型）
□ 数据去重与过期治理
□ 有 recall@k 与线上满意度双指标
□ 调优按"分块 → 模型 → 检索 → 重排"顺序
```
