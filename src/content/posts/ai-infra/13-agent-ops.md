### Demo 与生产的差距

```
Demo：一次对话、一个任务、人工盯着
生产：并发、长会话、失败重试、权限、成本、可观测
```

**"能跑通一次"和"能稳定跑一万次"之间隔着五道关**。

### 第一关：工具调用要"可验证"

```python
@tool
def query_order(order_id: str) -> dict:
    """按订单号查订单。order_id 必须是纯数字，否则报错。"""
    if not order_id.isdigit():
        raise ValueError("order_id must be numeric")
    return db.get_order(order_id)
```

**要点**：

```
① 每个工具的 docstring 就是"给模型的说明"（必须写清参数约束）
② 工具有明确的失败语义（抛异常而不是返回 "出错了"）
③ 返回结构化数据（不要让模型从字符串里抠字段）
```

**"工具返回一段自然语言"是 Agent 不稳定的头号原因**：

```
模型要"读懂"返回内容 → 幻觉 → 下一步动作错
```

### 第二关：上下文要"可裁剪"

```
长会话必然超上下文
→ 必须有"保留什么、丢弃什么"的策略
```

**三种策略**：

```
① 摘要（把早期对话压缩成要点）
② 检索（把历史存向量库，按需召回）
③ 结构化状态（把"事实"提炼成 KV，而不是保留原文）
```

**最可靠的是第三种**：

```json
{
  "user_id": "u123",
  "intent": "refund",
  "order_id": "456",
  "refund_amount": 99.00,
  "stage": "confirm"
}
```

**"状态外置"让 Agent 不依赖"记得住"**。

### 第三关：失败要能"有序退化"

```
① 工具失败 → 重试（有限次，指数退避）
② 重试仍失败 → 换工具/换路径
③ 都不行 → 明确拒答 + 转人工
```

**"无限重试"是成本与稳定性双杀**：

```
一个 Agent 卡在重试循环 → 烧钱 + 用户等不到结果
```

**必须有"最大步数 + 总超时"**：

```python
max_steps = 8
deadline = time.time() + 60
```

### 第四关：权限边界（最重要的安全关）

```
Agent 能调用的工具 = 它的攻击面
```

**分级**：

```
只读（查订单、查文档）      → 可放宽
写操作（改状态、发消息）    → 必须确认
资金/权限（退款、授权）     → 必须人工审批 + 限额
```

**三个必须做的事**：

```
① 工具级权限（不是"Agent 有全部权限"）
② 危险操作二次确认（人或规则）
③ 全量审计日志（谁、何时、调了什么、结果）
```

**"给 Agent 一个能删库的工具"是设计事故**。

### 第五关：成本与可观测

**成本结构**：

```
① 输入 token（上下文越长越贵）
② 输出 token（更贵）
③ 工具调用次数
④ 重试与并行
```

**降本三招**：

```
① 上下文裁剪（省输入）
② 缓存（相同问题命中缓存）
③ 模型分级（简单任务用小模型）
```

**可观测要看**：

```
① 每步的工具调用与参数
② 每步的 token 消耗
③ 失败率与重试次数
④ 端到端时延
⑤ 用户"纠正/重问"的比例（质量信号）
```

**"Agent 黑了盒"是最难调的状态**：

```
用户说"它答错了" → 你连它调了什么工具都不知道
```

### 五个"Demo 很好用上线就崩"的原因

**① 没限制步数**

```
模型陷入循环（调工具 → 结果不满意 → 再调）
→ 无限烧钱
```

**② 上下文无限增长**

```
长会话到 50 轮 → 超上下文 → 报错/截断 → 行为突变
```

**③ 工具返回不结构化**

```
模型"读不懂"→ 下一步决策错
```

**④ 没有幂等保护**

```
重试导致"重复下单/重复退款"
```

**⑤ 没有"拒答"路径**

```
模型被要求"必须回答" → 编造
```

**必须允许"我不知道，转人工"**。

### 一个"可上线"的骨架

```python
async def run_agent(user_input, state):
    for step in range(MAX_STEPS):
        if time.time() > deadline: return escalate(state)
        plan = await llm.plan(state, tools)
        if plan.action == "answer": return plan.answer
        tool = tools[plan.tool]
        try:
            result = await tool(**plan.args)
        except ToolError as e:
            state.errors.append(e); continue
        state = state.update(result)      # 结构化状态
        log(step, plan.tool, plan.args, result)
    return escalate(state)
```

**注意 `escalate`（转人工）是正常路径，不是异常路径**。

### 质量评估

```
① 建"评测集"（50–200 个真实任务，含正确期望）
② 每次改 prompt/工具后跑评测集（回归）
③ 指标：任务完成率、平均步数、错误率、人工介入率
```

**"凭感觉说'好像变好了'"是 Agent 开发最大的坑**。

### 检查清单

```
□ 每个工具 docstring 写清参数约束
□ 工具返回结构化数据
□ 有最大步数与总超时
□ 有限次重试 + 退避
□ 有转人工兜底
□ 上下文裁剪/状态外置
□ 工具级权限（不是全权限）
□ 危险操作二次确认
□ 全量审计日志
□ token 与调用次数可观测
□ 有评测集做回归
□ 关键写操作幂等
```
