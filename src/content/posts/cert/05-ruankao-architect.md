### 三科结构

| 科目 | 题型 | 时间 | 及格 |
| --- | --- | --- | --- |
| 综合知识 | 75 道单选 | 150 分钟 | 45/75 |
| 案例分析 | 3 道必答 + 2 选 1（约 5 题） | 90 分钟 | 45/75 |
| 论文 | 4 选 1，写 2000–3000 字 | 120 分钟 | 45/75 |

三科**同一考试周期内全部合格**才算通过（不同科目成绩不跨期保留）。

### 综合知识：分值分布

大致占比（历年稳定）：

```
架构设计（架构风格、质量属性、架构评估）   ~20%
系统可靠性（冗余、集群、容错）             ~10%
系统性能（评估、优化、负载均衡）           ~10%
信息系统安全                              ~10%
数据库（分布式、NoSQL、缓存）              ~10%
系统开发基础（UML、设计模式）              ~15%
项目管理（进度、成本、风险）               ~10%
新技术（云计算、大数据、AI、物联网）        ~5%
```

**送分题**：设计模式（23 种谁负责什么）、UML 图（用例/类/时序/状态）、质量属性（性能/可用性/可修改性/安全性/可测试性/易用性）。

必背的两个框架：

```
质量属性六项：性能、可靠性、可用性、安全性、可修改性、易用性
          （有的版本还含可测试性、功能性）
架构评估：敏感点、权衡点、风险点、非风险点
```

"敏感点/权衡点"是高频考点，混淆就丢分：

- **敏感点**：一个属性对另一个属性的影响（如"加密算法强度影响性能"）。
- **权衡点**：影响多个质量属性的决策（如"加密强度"同时影响安全性与性能）。
- **风险点**：可能导致失败的隐患。
- **非风险点**：明确可接受的约束。

### 案例分析：四类题型

**① 架构设计题**

给一个业务场景，问"你会选哪种架构风格/技术方案，说明理由"。

答题骨架：

```
① 场景特征（并发量、数据一致性要求、扩展性）
② 选型（分层/微服务/事件驱动/管道过滤器…）
③ 理由（对应特征逐条）
④ 代价与风险
```

关键：**理由必须与场景特征对应**，不要写通用好处。

**② 质量属性与架构评估题**

给架构描述，问"哪些是敏感点/权衡点"。

答题方法：找"某个设计决策影响了哪个质量属性"的句子，逐条标注。

**③ 数据库与分布式题**

常见：读写分离、分库分表、缓存一致性、分布式事务。

答题要点：

- 先给方案（如"读写分离 + 缓存"）。
- 再说"如何保证一致性"（延迟双删、binlog 订阅）。
- 最后说"故障时怎么办"。

**④ 计算题**

可靠性计算（串联/并联）、性能计算（响应时间、吞吐）、进度计算（关键路径）。

可靠度并联公式：

```
R = 1 - (1-R1)(1-R2)...
```

串联：

```
R = R1 × R2 × ...
```

这类题**只要公式对，就能拿满分**，别放弃。

### 论文：最难也最有套路

**结构（2500 字左右）**：

```
摘要（200–300 字）：项目背景 + 我用了什么方法 + 效果
正文：
  ① 项目背景与我的角色（300 字）
  ② 理论与方法（600 字，要有术语）
  ③ 实践过程（800 字，要具体：选型、遇到的问题、怎么解决）
  ④ 效果与数据（300 字）
  ⑤ 不足与改进（200 字）
结尾（100 字）
```

**八个高频主题**，每个准备一个真实项目素材：

1. 架构风格（分层 / 微服务 / 事件驱动）
2. 高可用设计
3. 高性能设计
4. 数据一致性
5. 系统安全设计
6. 云原生/容器化迁移
7. 大数据/数据中台
8. 系统集成与接口设计

**准备方法**：一个项目素材，套八个主题。素材要包含：

```
背景：什么业务、多大规模（QPS、数据量、用户数）
角色：我是架构师/技术负责人，负责什么决策
方法：用了什么（要有专业名词）
问题：遇到什么（要具体，如"跨库事务一致性"）
解决：怎么解决（要能说清原理）
数据：效果（P99 从 800ms 降到 120ms 之类）
```

**"背了但答不到点上"的三个原因**：

1. **没有数据**：全篇"显著提升"，阅卷人看不到量化。
2. **没有"我"**：写成"通常我们会…"，而不是"我在这个项目中…"。
3. **没有取舍**：只说好处不说代价，不像做过架构的人。

### 时间与复习节奏

| 阶段 | 时间 | 内容 |
| --- | --- | --- |
| 1 | 2 周 | 通读教材，画知识框架 |
| 2 | 3 周 | 刷 5 年真题（综合知识），错题归因 |
| 3 | 2 周 | 案例题专项（每类 5 道，手写答案） |
| 4 | 2 周 | 论文：准备 2 个项目素材，写 4 篇完整论文 |
| 5 | 考前 1 周 | 只复习错题 + 背论文骨架 |

**真题是最有效的投入**：综合知识重复率很高，案例题的题型也高度稳定。

### 三个应试技巧

1. **案例题先读问题再读材料**，带着问题找信息，效率翻倍。
2. **论文先写骨架再填内容**，避免写一半发现跑题。
3. **综合知识不纠结**：不会的题标记后跳过，最后统一蒙（不要空着）。

### 一句话总结

软考架构师考的不是"记住多少"，而是**能不能把一个技术决策讲清理由、代价与效果**。论文就是这道题的放大版。
