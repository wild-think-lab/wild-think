### 两种活动别混为一谈

| | 游戏日（Game Day） | 混沌实验（Chaos） |
| --- | --- | --- |
| 形式 | 人为设定场景，团队按流程处置 | 自动注入故障，观察系统行为 |
| 目的 | 练人（流程、协作） | 验系统（自愈、降级、限流） |
| 频率 | 季度 | 可持续（小剂量） |
| 风险 | 低（可以选非生产） | 需要严格控制 |

**先做游戏日，再做混沌实验**：人还没练熟就自动注入故障，等于制造事故。

### 五个低风险起步实验

按风险从低到高：

**① 单实例终止**

```bash
# 随机杀一个 Pod，验证副本与流量转移
kubectl delete pod -n prod -l app=api --field-selector=status.phase=Running | head -1
```

预期：流量切到其他副本，错误率无显著变化。若错误率飙升 → PDB/探针/连接池有问题。

**② 依赖延迟注入**

给某个下游加 200ms 延迟，验证超时与重试是否合理。

```yaml
# 用 toxiproxy 或 Istio fault injection
fault:
  delay: { fixedDelay: 200ms, percentage: { value: 50 } }
```

预期：P99 上升但可控，超时链不被击穿。

**③ 依赖错误注入**

让某依赖返回 5xx 30% 的请求。

预期：熔断生效、降级路径被触发、用户看到"部分功能不可用"而不是全站报错。

**④ 网络分区**

断开两个可用区之间的通信（或阻断到某节点的流量）。

预期：不出现脑裂导致的数据不一致，流量切换到健康区。

**⑤ 资源压力**

给节点加压（CPU/内存/磁盘），验证调度与驱逐。

```bash
# 用 stress-ng 在测试节点上压
stress-ng --cpu 8 --timeout 60s
```

预期：QoS 低的 Pod 被驱逐，关键服务不受影响。

### 爆炸半径控制

四条硬规则：

1. **一次只注入一个变量**：同时改两个，出问题不知道是哪个。
2. **限定范围**：只影响 1 个副本 / 1 个可用区 / 1% 流量。
3. **有中止开关**：一键停止注入（不只是"人跑过去 Ctrl-C"）。
4. **有观测基线**：注入前后的指标对比，否则"看起来还好"是主观判断。

```yaml
experiment:
  scope: { namespace: prod, selector: app=api, max_targets: 1 }
  duration: 10m
  abort_if:
    - error_rate > 0.05
    - p99_latency > 1s
```

`abort_if` 是必须的：预设"什么情况下立刻停"，而不是靠人盯着。

### 观测什么

注入前后对比三个层面：

```
① 用户层：错误率、P99、成功率（业务指标）
② 系统层：自愈是否发生（副本是否重建、流量是否切换）
③ 流程层：告警是否触发、值班是否收到、Runbook 是否可用
```

**第三层最容易被忽略，也最有价值**：系统自愈了但没人知道，等于失去了一次学习机会。

### "演练了但没学到东西"

三个原因：

1. **只验了 happy path**：注入的故障太轻，系统轻松扛住，什么也没暴露。
2. **没有记录**：事后只记得"跑通了"，没有数据。
3. **没有改进项**：演练结束没人负责改，下次还一样。

正确的产出：

```markdown
## 实验：终止 1 个 api 副本
结果：错误率 0.02% → 0.6%（持续 40 秒）
意外发现：连接池未复用，新副本冷启动需要预热 30 秒
改进：
1. 加"预热"逻辑（owner: 张，两周）
2. 探针 initialDelay 从 5s 调到 20s（owner: 李，已完成）
3. 记录到 Runbook（owner: 王，一周）
```

### 生产还是非生产

| 阶段 | 环境 |
| --- | --- |
| 首次实验 | 预发/测试 |
| 成熟后 | 生产，小剂量（1% 流量、1 个实例） |
| 高风险实验（网络分区、数据层） | 生产需审批 + 业务低峰 |

原则：**生产是唯一能验证真实行为的环境**，但必须小剂量、可中止、有观测。

### 起步路径

```
第 1 月：一次游戏日（模拟"数据库主库宕机"，走流程）
第 2 月：非生产做"杀实例"与"延迟注入"
第 3 月：生产做"杀 1 个副本"，观察 30 分钟
第 4 月：生产做"依赖 5xx 注入"，验证熔断与降级
之后：季度固定一次游戏日 + 常态化小剂量实验
```

每次只前进一小步，比一次上全套更容易持续。

### 一句话总结

混沌工程的价值不在"证明系统很强"，而在**找出那些"以为会自愈但其实不会"的地方**。找出来并修掉，才叫演练成功。
