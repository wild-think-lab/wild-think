### 先拆账单（这一步最重要）

```
① 计算（ECS/EC2、函数、GPU）
② 存储（云盘、对象存储、快照）
③ 网络（带宽、出网流量、跨区流量）
④ 数据库与中间件（RDS/Redis/MQ 的规格费）
⑤ 其他（监控、CDN、日志、备份）
```

**"只盯着计算费"是最常见的盲点**：

```
很多团队的"出网流量费"能占到总账单 30%+
```

### 六个动作

**① 找到"低利用率的资源"**

```
现象：100 台 4C8G，平均 CPU 使用率 8%
→ 不是"业务轻"，是"规划过头"
```

**做法**：

```
① 按"7 天 P95 使用率"评估
② 低于 20% 的考虑降配或合并
③ 但注意内存（不能只看 CPU）
```

**降配的风险**：

```
内存降下去后 OOM → 得不偿失
→ 内存要看"实际 working set"，不是"看起来空闲"
```

**② 处理"僵尸资源"**

```
① 已下线但没释放的实例
② 过期的快照（云盘快照按容量计费）
③ 没人访问的负载均衡/域名/CDN 配置
④ 测试环境 7×24 开着（其实只工作日用）
```

**做法**：

```
① 打标签（owner/purpose/expire）
② 每月"资源盘点"（没人认领就下线）
③ 测试环境按需启停（定时开/关）
```

**③ 存储分层**

```
热数据 → 高性能云盘
冷数据 → 归档/低频存储（便宜很多）
快照 → 定期清理（没人会主动清）
```

**"对象存储的版本控制 + 不清理旧版本"是隐性大头**：

```
每次覆盖留一份 → 存储翻几倍
```

**④ 网络与带宽**

```
① 静态资源上 CDN（减少出网）
② 跨区流量（能同区就同区）
③ 按带宽计费 vs 按流量计费（按峰值选方式）
④ 对象存储的出网流量最贵（用 CDN 回源）
```

**"图片直连对象存储"是最常见的带宽浪费**。

**⑤ 计费方式的选择**

```
预留实例（包年包月）：便宜但绑定
按量付费            ：灵活但单价高
节省计划/承诺消费  ：中等
```

**判断**：

```
利用率 > 70% 且长期稳定 → 预留
波动大/短期项目 → 按量
```

**"全部按量"往往比"预留+按量混合"贵 30%+**。

**⑥ 数据库与中间件的规格**

```
① RDS 的规格（CPU/内存/存储）常被"一次买大"
② 只读实例按需（不是每个库都配）
③ Redis 集群 vs 单机（小业务不需要集群）
④ 备份保留策略（备份也占存储）
```

### 五个"越省越贵"的做法

**① 把生产降配到"刚好够"**

```
省了 20% 费用 → 大促时扩容 + 故障损失 ≫ 省下的钱
```

**"成本优化不能牺牲可用性"**。

**② 关掉监控/日志保留**

```
省了日志费 → 出事时无法定位 → 故障时长翻倍
```

**③ 用便宜的低质量线路**

```
网络抖动 → 重试 → 实际流量费更高 + 用户体验差
```

**④ 把数据库迁到"更便宜的规格"**

```
IOPS 不够 → 慢查询 → 应用层加缓存 → 总体成本反而上升
```

**⑤ 不看"单位成本"只看"总价"**

```
A 方案 1 万/月 支撑 100 万请求
B 方案 8 千/月 支撑 50 万请求
→ B 的"每万请求成本"更高
```

### 一个"月度成本评审"的模板

```markdown
## 本月账单
- 总额：¥xx,xxx（环比 +x%）
- 计算：xx%  存储：xx%  网络：xx%  数据库：xx%

## Top 5 成本项
1. xx 实例集群（¥x,xxx）—— 利用率 12%，建议降配
2. 对象存储（¥x,xxx）—— 含 2TB 旧快照，建议清理

## 本月动作
- 下线 5 台僵尸实例（月省 ¥xxx）
- 快照保留从 30 天改 7 天（月省 ¥xxx）

## 风险
- xx 服务降配后需观察 2 周
```

**"每月一次、有具体数字"** 比"季度大讨论"有效得多。

### 成本与架构的关系

```
架构决定成本结构，运维决定成本效率
```

**三个架构层面的成本杠杆**：

```
① 无状态化（更容易弹性，减少闲置）
② 缓存分层（减少数据库规格与流量）
③ 异步化（削峰，减少峰值容量）
```

**"先改架构再抠账单"往往收益更大**。

### 检查清单

```
□ 拆清账单（五类：计算/存储/网络/数据库/其他）
□ 有资源清单（owner/purpose/expire 标签）
□ 按 P95 使用率评估低利用率资源
□ 清理僵尸实例与过期快照
□ 存储分层（热/冷/归档）
□ 静态资源上 CDN（减少出网）
□ 计费方式按利用率选（预留/按量混合）
□ 数据库规格定期复核
□ 不牺牲可用性与可观测来省钱
□ 看"单位成本"而非总价
□ 每月一次成本评审（带数字）
□ 优先用架构手段（无状态/缓存/异步）
```
