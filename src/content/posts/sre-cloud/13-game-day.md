### 演练 vs 压测

```
压测：验证"能扛多少"（容量）
演练：验证"出事时能不能处理"（能力）
```

**演练考的是人和流程，不只是系统**：

```
① 告警能不能及时触发
② 值班的人知不知道第一步做什么
③ Runbook 里的命令还能不能跑通
④ 沟通链路（谁通知谁）顺不顺
```

### 一次演练的完整流程

```
① 定目标（这次练什么，成功标准是什么）
② 选项目（从低风险开始）
③ 通知（谁会受影响，什么时候）
④ 执行（按脚本，有回滚开关）
⑤ 观察（告警是否触发、响应是否及时）
⑥ 复盘（记录时间线，找流程漏洞）
```

**关键是 ④ 的"回滚开关"**：演练必须能立刻停。

### 六个安全的演练项目

| 项目 | 做法 | 验证什么 |
| --- | --- | --- |
| 单实例故障 | 停一个 Pod | 自愈与告警 |
| 节点下线 | 关闭一个 worker（先迁走 Pod） | 调度与容量 |
| 依赖超时 | 用 iptables 丢包到数据库 | 降级与熔断 |
| 慢查询 | 人为制造慢 SQL | 超时与告警 |
| 磁盘满 | 用 `fallocate` 填满临时盘 | 驱逐与告警 |
| 证书过期 | 用一张短期证书 | 监控是否提前告警 |

**从第一个开始**：停一个 Pod 是风险最低、收益最高的演练（能发现"自愈没配好"、"告警太慢"）。

### 保证"演的不会真出事"

```
① 只在预发/灰度环境做高风险项目
② 生产只做"可逆且影响可控"的项目
③ 有时间窗口（避开业务高峰）
④ 有"一键恢复"命令，且演练前验证过
⑤ 有人盯（不是"设完就跑"）
⑥ 有止损条件（如错误率 > 1% 立即停止）
```

**止损条件必须提前写下来**：

```
例：本次演练，若以下任一条件成立，立即恢复：
- 5xx 率 > 0.5%
- P99 延迟 > 500ms
- 下单成功率下降 10%
```

### 演练脚本模板

```markdown
# 演练：订单服务单实例故障

## 目标
验证：Pod 重启后 30 秒内恢复；告警在 1 分钟内触发；值班人员按 runbook 完成确认

## 前置
- 服务 3 副本
- PDB minAvailable=2
- 已通知业务方（10:00–10:30 窗口）

## 步骤
1. 记录基线：curl 打 10 次 /health，记录耗时
2. `kubectl delete pod <one-pod> -n prod`
3. 观察：新 Pod 启动时间、endpoints 恢复时间
4. 检查告警是否在 1 分钟内到达值班群
5. 打断值人员：按 runbook 走一遍

## 止损条件
- 5xx 率 > 0.5% 持续 2 分钟 → 立即回滚（恢复副本数、检查配置）

## 记录
| 时间 | 事件 | 备注 |
| --- | --- | --- |
| 10:02 | 删 Pod | |
| 10:02:20 | 告警到达 | 延迟 20s |
| 10:02:45 | 新 Pod Ready | 45s |
```

### 演练中最常见的四个发现

**① 告警没响**

```
原因：告警规则只针对"全部副本挂"，单实例挂不告警
发现后：补充"单实例异常"的告警（或至少记录事件）
```

**② Runbook 里的命令过期了**

```
runbook 写 "kubectl --namespace=prod get pods"，但命名空间已改成 prod-api
发现后：修正并加"最后验证日期"
```

**③ 值班的人不知道找谁**

```
升级路径写了"联系负责人"，但没写电话
发现后：把联系人与电话写进 runbook
```

**④ 自愈没配好**

```
Pod 挂了但没自动重建（因为用了静态 Pod 或 job）
发现后：改部署方式或加守护
```

**"演练的真正产出是流程漏洞清单"**，不是"系统没问题"这个结论。

### 频率与节奏

```
每月：1 次低风险演练（单实例、依赖超时）
每季：1 次中等风险（节点下线、磁盘满）
每年：1 次高影响（机房切换/灾备切换，需全面准备）
```

**新系统上线后一个月内必须演练一次**：新东西的流程最不靠谱。

### 复盘怎么写

```
① 事实时间线（几点几分发生了什么）
② 预期 vs 实际（差在哪）
③ 流程漏洞（runbook、告警、权限、沟通）
④ 改进项（谁、什么时候、怎么验证）
⑤ 下次演练要验证什么
```

**不要写成"系统表现良好"**：演练的价值在于暴露问题，没有问题的演练通常意味着"演练太浅"。

### 检查清单

```
□ 有演练计划（月度/季度/年度）
□ 每个演练有目标与成功标准
□ 有止损条件且提前写下
□ 有回滚命令且验证过
□ 通知了受影响方
□ 记录时间线
□ 复盘产出"流程漏洞清单 + 改进责任人"
□ 新系统上线一个月内演练过
```
