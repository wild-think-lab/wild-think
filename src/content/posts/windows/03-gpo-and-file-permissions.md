### 组策略（GPO）：一次配置，全网机器照做

典型场景：全公司 200 台电脑，要统一改屏保时间、禁用 U 盘、给财务部装一个打印机。

手动做 200 次是不可能的，所以有了 GPO：

```text
域控 → 组策略管理（GPMC）→ 新建策略 → 链接到某个 OU → 客户端 gpupdate 生效
```

命令行检查：

```powershell
gpupdate /force
gpresult /r               # 当前用户/计算机应用了哪些策略
gpresult /h C:\gpo.html   # 生成完整报告，含冲突与拒绝原因
```

`gpresult /h` 是排"策略为什么没生效"的唯一正确入口——它会明确写"被谁拒绝"。

### 策略没生效的五个原因

1. **链接到了错的 OU**：策略只对链接的 OU 及其子 OU 生效。
2. **安全筛选没包含目标**：默认只对"Authenticated Users"生效，改过就可能漏。
3. **WMI 筛选条件写错**：按型号、系统版本过滤时容易写错。
4. **客户端没刷新**：默认 90 分钟一次，测试要 `gpupdate /force`。
5. **用户配置 vs 计算机配置**：放错位置，另一头怎么刷新都不会生效。

### 文件共享：两层权限的叠加

访问 `\\FS01\share\财务` 时，权限被**两道闸门**限制：

```text
第一道：共享权限（Share）      → 只对"通过网络访问"生效
第二道：NTFS 权限（Security）   → 对本地和网络访问都生效
最终权限 = 两者中更严格的那个
```

所以"我给了完全控制还是打不开"，通常是 NTFS 那层没过。判断顺序：

```powershell
Get-SmbShare -Name share | Select-Object *
Get-SmbShareAccess -Name share
Get-Acl \\FS01\share\财务 | Format-List
icacls \\FS01\share\财务
```

### 推荐的权限设计

| 层级 | 做法 | 原因 |
| --- | --- | --- |
| 共享权限 | 给 `Authenticated Users` 只读或"更改" | 共享层尽量宽，逻辑交给 NTFS |
| NTFS 权限 | 按部门组（如 `GG-Finance-RW`）授予 | 组驱动，人员变动只改组 |
| 目录结构 | 部门文件夹 → 组 → 权限 | 别按人授权，人一多必乱 |

组驱动（AGDLP）是标准做法：**账号 → 全局组 → 域本地组 → 权限**。看着绕，但人员、权限各自独立变化，长期最省事。

### 两个高频坑

**① 继承被阻断**：某个子目录右键关了"继承"，父目录授权不再下沉。用 `icacls` 看输出里有没有 `(I)` 标记，没有就是断链了。

**② 拒绝权限优先**：显式"拒绝"会压过所有"允许"。排查时先看有没有红色的拒绝项。

### 验证一次完整访问

```powershell
# 用某个域账号模拟访问，而不是拿管理员账号测
runas /user:CORP\zhangsan cmd
net use Z: \\FS01\share
dir Z:\财务
```

管理员测试永远能通，用真实账号才有意义。

### 本章要点

- GPO 靠 OU 链接生效，排查先跑 `gpresult /h`。
- 共享权限 + NTFS 权限取更严格者，问题多在 NTFS 层。
- 权限按"组"给，不按"人"给。
- 继承被阻断、显式拒绝，是两个最隐蔽的坑。
