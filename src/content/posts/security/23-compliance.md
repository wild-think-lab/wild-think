### 等保的五个方面

```
① 安全物理环境（机房）
② 安全通信网络（边界/网络架构）
③ 安全区域边界（访问控制/入侵防范）
④ 安全计算环境（主机/应用/数据）
⑤ 安全管理中心（审计/集中管控）
+ 管理制度（文档部分）
```

**运维主要扛 ②③④⑤**，物理环境与制度文档另有负责人。

### 三级最常见的条款 → 对应动作

**① 身份鉴别**

```
要求：双因素、登录失败处理、超时退出
落地：SSH 用密钥 + MFA（或堡垒机统一认证）
      配置 MaxAuthTries / ClientAliveInterval
```

**② 访问控制**

```
要求：最小权限、默认拒绝
落地：防火墙默认拒绝 + 白名单；sudo 细粒度
```

**③ 安全审计**

```
要求：覆盖每个用户、审计记录不可删改、留存 ≥ 6 个月
落地：审计日志集中到日志平台（只写不改）
      rsyslog/auditd 转发，本地保留 + 异地留存
```

**"审计记录留存 6 个月"是硬指标**，很多单位卡在这。

**④ 入侵防范**

```
要求：最小安装、关闭多余端口、漏洞扫描、入侵检测
落地：基线加固脚本 + 定期漏扫 + 主机 HIDS
```

**⑤ 恶意代码防范**

```
要求：防病毒/防恶意代码
落地：主机 EDR/杀毒，定期更新特征库
```

**⑥ 数据完整性/保密性**

```
要求：传输与存储加密
落地：TLS 全站、数据库加密/字段加密、备份加密
```

**⑦ 数据备份恢复**

```
要求：本地备份 + 异地备份、定期演练
落地：3-2-1 + 恢复演练记录
```

**⑧ 剩余信息保护**

```
要求：释放的资源要被清空
落地：磁盘/内存回收前擦除（虚拟机镜像回收、存储退役流程）
```

**⑨ 集中管控**

```
要求：统一监控、统一审计、统一管理
落地：堡垒机 + 集中日志 + 统一监控（三件套）
```

### 运维能直接做的四件事

**① 基线加固**

```bash
# 常见项：SSH、密码策略、SELinux、审计
# 用自动化工具批量执行（Ansible role）
```

**② 集中日志**

```
所有主机/网络设备/应用 → 日志平台（只写）
保留期 ≥ 6 个月
```

**③ 堡垒机**

```
所有运维操作经堡垒机（带录屏/命令审计）
禁止直连生产
```

**④ 定期扫描与整改闭环**

```
漏扫 → 出报告 → 排期修复 → 复测 → 归档
```

**"有报告没整改"是测评最常扣分的点**。

### 五个"为了过测评而做"的无效合规

**① 日志开了但没人看**

```
要求是"能审计"，实际是"从不审计"
→ 出了事照样查不到
```

**② 堡垒机只做跳板**

```
只转发不记录/不录屏 → 审计要求不满足
```

**③ 备份有但没演练**

```
条款要求"定期演练"，只有备份没有演练记录 → 不达标
```

**④ 补丁"计划中"**

```
高危漏洞长期不修，只在报告里写"计划整改"
→ 复测不通过
```

**⑤ 制度文档与实际两张皮**

```
文档写"每季度评审"，实际一年没开过会
→ 现场访谈一问就露
```

### 一个"整改顺序"

```
① 先补"硬指标"（日志留存、备份演练、双因素）
② 再补"面上的"（基线加固、漏扫闭环）
③ 最后补"制度的"（评审记录、培训记录）
```

**"硬指标"最容易被卡，先做**。

### 检查清单

```
□ 双因素（关键系统）
□ 登录失败限制 + 会话超时
□ 防火墙默认拒绝 + 白名单
□ 审计日志集中 + 留存 ≥ 6 个月
□ 基线加固（批量执行）
□ 定期漏扫 + 整改闭环
□ 主机防护（HIDS/EDR）
□ 全站 TLS
□ 备份 + 异地 + 演练记录
□ 堡垒机（记录/录屏）
□ 集中监控
□ 制度文档与实际一致
```
