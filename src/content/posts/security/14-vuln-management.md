### 扫描完的三种结局

```
① 500 个漏洞，看一眼，关掉报告（最常见）
② 全都要修，修到一半放弃
③ 定级 + 排期 + 验证，持续收敛（正确但少见）
```

**问题不是"漏洞多"，而是"没有处理规则"**。

### 定级的两个维度

**CVSS 分数只是起点**，必须叠加"实际可利用性"：

```
优先级 = CVSS × 是否公网可达 × 是否已有 PoC × 是否关键资产
```

一张实用的四档表：

| 级别 | 条件 | 修复时限 |
| --- | --- | --- |
| P0 | 公网可达 + 高危 + 已有公开 PoC | 24 小时 |
| P1 | 公网可达 + 高危 | 7 天 |
| P2 | 内网 + 高危，或公网 + 中危 | 30 天 |
| P3 | 内网 + 中低危，或需高权限才能利用 | 季度/下次维护 |

**"需高权限才能利用"要降级**：已经拿到 root 的人再提权意义有限，优先级应让给"未授权可达"的漏洞。

### 降噪：先处理"扫描器误报"

三类高频误报：

| 类型 | 判断方法 |
| --- | --- |
| 版本号误报 | 扫描器只看 banner（如只看 nginx 版本号，但已打补丁回移） |
| 不可达服务 | 报告说"开放"，实际被防火墙拦 |
| 无实际利用链 | 组件有漏洞，但相关功能未启用 |

```bash
# 手工复核端口是否真的可达
nmap -Pn -p <port> <ip>
# 复核版本是否真受影响
nginx -v; rpm -q nginx
```

**误报比例常常 30–50%**。先把误报清掉，剩下的才是真工作量。

### 修复节奏

```
每周：处理新增 P0/P1（滚动）
每月：批量处理 P2（一次维护窗口）
每季：P3 与结构性整改
```

**不要攒到一起修**：攒 300 个再修，等于没有任何系统是安全的。

### 例外管理（必须有）

有些漏洞"不能修"（业务依赖老版本、厂商不再支持）：

```
例外必须有三样：
① 原因（为什么不能修）
② 补偿措施（WAF 规则、网络隔离、加固配置）
③ 到期日（到期必须重新评估）
```

**没有到期日的例外 = 永久漏洞**。

### 验证：修了要证明修了

```
① 扫描器复扫（同一规则集）
② 手工验证（对 P0/P1 做一次实际利用尝试）
③ 记录留痕（谁在什么时候修的、验证结果）
```

只做①不够：**换了版本号但配置没改的情况很常见**。

### 一次真实收敛（6 个月）

**起点**：首次扫描 512 个问题（P0 6 / P1 43 / P2 178 / P3 285）。

**第 1 月**：

```
- 手工复核，剔除误报 140 个
- 处理 6 个 P0（关端口、升级、加 WAF 规则）
- 建立例外台账（12 个暂不修的，全部写了补偿措施与到期日）
```

**第 2–3 月**：

```
- 43 个 P1 分批修完（每周维护窗口）
- 引入"新增代码必须过依赖扫描"（CI 阻断高危）
```

**第 4–6 月**：

```
- P2 收敛到 30 个以内
- P3 中 60% 通过"下线旧系统"直接消除
- 每月复扫，新增数从 40/月 降到 8/月
```

**关键动作**：不是"突击修复"，而是**让新增速度降下来**（CI 阻断 + 下线旧系统）。

### 让漏洞不再新增

```
① 依赖扫描进 CI（高危阻断合并）
② 镜像扫描进发布流水线
③ 每月固定补丁窗口
④ 新系统上线前过安全评审（避免引入老组件）
⑤ 定期下线不用的系统（最好的"修复"）
```

### 三个常见误区

| 误区 | 后果 |
| --- | --- |
| 只看 CVSS 分数排序 | 修了一堆内网低可利用的，漏了公网可利用的 |
| 把"升级"当唯一手段 | 老系统不能升 → 直接僵住，要会用"补偿措施" |
| 修完不验证 | 以为修了，其实扫描器还在报 |

### 报表怎么写给老板看

```
本月漏洞情况
- 新增 12 个（P0 0 / P1 2 / P2 4 / P3 6）
- 已修复 21 个
- 当前存量 156 个（P0 0 / P1 3 / P2 41 / P3 112）
- 例外中 9 个（均有补偿措施与到期日）
- 趋势：连续 3 个月下降
- 本月风险最高的 3 个：[...] 及处理计划
```

**用"存量与趋势"汇报，不用"总数"**：总数永远很多，趋势才有意义。

### 检查清单

```
□ 有定级规则（CVSS + 可达性 + PoC + 资产重要性）
□ 有误报复核流程（不直接信扫描器）
□ 修复有时限（P0 24h / P1 7d / P2 30d）
□ 例外有原因、补偿措施、到期日
□ 修复后有验证（复扫 + 手工）
□ 依赖/镜像扫描进 CI
□ 每月固定补丁窗口
□ 每季度下线不用的系统
□ 报表用存量与趋势
```
