### 它解决的不是"禁止"，而是"可追溯"

```
禁止直连：靠制度与网络策略（总有人绕）
堡垒机：所有运维流量必须经过它，且被记录
```

**"只发文件要求大家走堡垒机"** → 三个月后没人遵守。

### 四个能力

```
① 统一入口（SSH/RDP/数据库/Web）
② 身份与权限（谁能登哪台、能做什么）
③ 会话审计（录屏/命令/文件传输）
④ 阻断与告警（高危命令、异常登录）
```

### 部署模式

```
① 代理模式（流量经堡垒机转发）
   优点：能审计、能阻断
   缺点：带宽与性能要够

② 直连模式（只做认证与记录）
   优点：性能好
   缺点：审计不完整（只记录登录，不记录操作）
```

**"只做认证"** 等于只记了"谁进过门"。

### 网络怎么强制

```
① 服务器只允许堡垒机 IP 访问 22/3389
② 运维人员网络只能访问堡垒机
③ 双因素认证（密码 + OTP/证书）
④ 有"例外清单"且定期复核
```

**"服务器 22 对全网开放"** → 堡垒机形同虚设。

### 审计能看到什么

```
SSH：命令级（含录制）、文件传输
RDP：屏幕录制 + 键盘记录（视方案）
数据库：SQL 语句
Web：请求 URL 与响应（视方案）
```

**边界**：

```
① 加密隧道内的内容（如再套一层 SSH）看不到
② 剪贴板/截图 难完全覆盖
③ 大流量传输需要额外策略
```

### 五个"上了堡垒机等于没上"

**① 服务器仍开放直连**

```
运维绕过堡垒机直连 → 审计断链
```

**② 共享账号**

```
所有人用 root/同一个账号 → 无法定位到人
```

**③ 审计只存本地**

```
攻击者先删日志 → 无迹可查（要实时外送）
```

**④ 高危命令不阻断**

```
rm -rf / 记录下来了，但已经执行了
```

**⑤ 没有定期复核权限**

```
离职/转岗后仍能登（权限只增不减）
```

### 一个"够用"的建设顺序

```
1) 服务器网络层只允许堡垒机
2) 一人一账号 + 双因素
3) 会话录制 + 日志实时外送
4) 高危命令阻断（rm/mkfs/drop 等）
5) 权限季度复核 + 离职即时回收
```

### 检查清单

```
□ 服务器侧只允许堡垒机访问
□ 一人一账号（禁共享）
□ 双因素认证
□ 会话录制（命令/文件/屏幕）
□ 审计日志实时外送（不可被本地删除）
□ 高危命令阻断或二次确认
□ 权限矩阵与季度复核
□ 离职/转岗即时回收
□ 有例外访问的审批与记录
□ 有"绕过堡垒机"的检测
```
