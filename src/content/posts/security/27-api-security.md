### 四类风险

```
① 未鉴权（谁都能调）
② 越权（能调但不是你的数据）
③ 滥用（刷接口/拖库）
④ 重放（截获请求重复提交）
```

**"有登录 ≠ 有鉴权"** —— 越权是最常见的一类。

### ① 鉴权的三种方式

```
Session + Cookie  ：适合浏览器，需 CSRF 防护
Token（JWT）      ：无状态，适合多端；要处理吊销/过期
签名（HMAC）      ：服务间调用，防篡改
```

**JWT 的坑**：

```
① 不要放敏感信息（base64 不是加密）
② 一定要校验 alg（防 alg=none 攻击）
③ 过期时间短 + refresh token
④ 需要"主动吊销"时要有黑名单/版本号
```

### ② 越权（最常被忽略）

```
水平越权：用户 A 用 ID 访问用户 B 的数据
垂直越权：普通用户访问管理员接口
```

**防护**：

```python
# 错：只校验"登录了"
if user: return db.get_order(order_id)

# 对：校验"这个订单属于我"
order = db.get_order(order_id)
if order.user_id != user.id: raise Forbidden()
```

**"对象级授权（object-level authorization）"** 是 OWASP API 第一风险。

**统一做法**：

```
所有"按 ID 取资源"的接口，都做"归属校验"
```

### ③ 限流的四个维度

```
① 全局（保护自身）
② 按用户/租户（配额）
③ 按 IP（防刷，但 NAT 后会误伤）
④ 按接口（贵的接口单独限）
```

**"只按 IP 限流"** 在移动网络/公司出口会误伤大量正常用户。

**"关键接口要按用户限"**（如短信、支付、导出）。

### ④ 重放防护

```
① 时间戳（±5 分钟窗口）
② nonce（一次性随机数，服务端记一段时间）
③ 签名（含 method+path+body+timestamp+nonce）
```

```python
sign = hmac_sha256(secret, f"{method}\n{path}\n{ts}\n{nonce}\n{body_sha256}")
```

**"只校验签名不校验时间戳"** → 签名可被无限重放。

### 五个"加了鉴权还是被越权"

**① 只在网关鉴权，服务不校验**

```
网关放行后，服务认为"肯定是合法用户"
→ 内部调用/绕过网关即可越权
```

**② 权限检查用了"客户端传来的角色"**

```
header 里 X-Role: admin → 自己伪造
```

**③ 列表接口漏了过滤**

```
分页接口没加"只返回属于我的"
→ 一次拖走全量数据
```

**④ 批量接口逐个校验漏了**

```
batchGet(ids) 只校验了第一个
```

**⑤ 导出/日志接口有全量权限**

```
"只有管理员能看"但导出接口没做校验
```

### 一个"三层"的防护模型

```
① 网关：认证、限流、基础 WAF
② 服务：对象级授权（每个接口自己校验）
③ 数据层：字段级权限（敏感字段脱敏）
```

**"只在网关做"** 是最常见的结构性错误。

### 敏感数据与响应

```
① 不返回不必要字段（按需 select）
② 敏感字段脱敏（手机号/身份证）
③ 错误信息不泄露内部细节（堆栈/SQL）
```

**"接口返回了完整用户对象（含内部字段）"** 是常见的数据泄露。

### 检查清单

```
□ 所有接口都鉴权（不只网关）
□ 对象级授权（归属校验）
□ 列表/批量接口逐项校验
□ 令牌校验 alg + 短过期
□ 关键接口按用户限流
□ 有重放防护（时间戳 + nonce）
□ 敏感字段脱敏
□ 错误信息不泄露内部
□ 导出接口单独鉴权 + 审计
□ 有 API 调用审计日志
```
