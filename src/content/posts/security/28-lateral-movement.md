### 攻方的五条路径

```
① 凭据（明文密码/票据/SSH 密钥）
② 信任（免密登录、域信任、K8s SA token）
③ 管理面（数据库/Redis/管理后台）
④ 编排层（Ansible/Jenkins/K8s API）
⑤ 共享（SMB/NFS/内网 WebDAV）
```

**"内网很安全"** 是最大的错觉——攻方在内网比在外网舒服得多。

### ① 凭据是最快的路径

```
明文密码出现在：脚本、配置文件、历史命令、日志
票据（Kerberos）可在内存中提取
SSH 私钥常被放在 ~/.ssh 且权限宽松
```

**"一台机器上有到所有机器的 SSH 密钥"** → 一次失守全线失守。

**防御**：

```
① 密钥不放生产机（用跳板/证书签发）
② 短时证书（SSH CA，几小时有效）
③ 凭据集中管理（Vault）
```

### ② 信任关系

```
- 域：域管理员 → 所有机器
- 免密 SSH：A 到 B 无需密码
- K8s：Pod 里的 SA token → API
- 云：实例角色（IAM Role）→ 云资源
```

**"Pod 里的 token 能 list secrets"** → 一个 RCE 变成全集群失守。

**防御**：

```
① 域管理员分层（不登录普通工作站）
② 免密关系最小化（能不用就不用）
③ Pod 不自动挂载 SA token
④ 实例角色最小权限
```

### ③ 管理面（最容易被忽视）

```
Redis 未鉴权 → 写 crontab / 写 SSH key
MySQL 弱口令 → 读数据 / 提权（UDF）
Docker API 2375 → 直接起 privileged 容器
管理后台弱口令 → 一堆功能
```

**"Redis 在内网所以不设密码"** → 这是最常见的横向跳板。

**防御**：

```
① 所有中间件都要鉴权（即使在内网）
② 管理面只允许跳板访问
③ 2375 绝对不暴露（用 2376 + TLS）
```

### ④ 编排层

```
Jenkins：能执行任意命令（等于 root）
Ansible：控制节点有所有机器的密钥
K8s：有集群权限 = 能起 Pod 挂宿主机
```

**"Jenkins 控制台没鉴权"** = 直接拿到所有部署机的权限。

**防御**：

```
① CI/CD 平台强认证 + 最小权限
② 凭据由平台托管（不落在 job 脚本里）
③ 编排层与生产网络隔离（只放行必要）
```

### ⑤ 共享

```
SMB 共享 Everyone 可写 → 投放恶意文件
NFS 无 restrictions → 读写他人数据
```

**防御**：

```
① 共享按需创建、最小权限
② 关闭匿名访问
③ 定期审计共享清单
```

### 检测点（防守方能看到什么）

```
① 异常的"认证成功但来源异常"（4624 / ssh 成功日志）
② 一台机器短时间内连接大量其他机器的 22/445/3389
③ 内网出现"端口扫描"特征
④ 凭据被使用在"从未登录过的机器"
⑤ 管理面（2375/6379/3306）出现非预期来源
```

**"横向移动的流量特征很明显"** —— 如果有人在看。

### 五个"内网很安全"的错觉

**① "内网没有攻击者"**

```
边界被突破后，攻击者就在内网
```

**② "内网可以明文"**

```
内网嗅探 + ARP 欺骗 → 明文协议全暴露
```

**③ "只有运维能进内网"**

```
VPN、堡垒机、第三方、IoT 设备都在内网
```

**④ "分段了就安全"**

```
分段不配策略 = 只是"多几个网段"
```

**⑤ "有防火墙就够了"**

```
防火墙管不住"合法凭据的合法连接"
```

### 一个"最小成本"的加固

```
① 管理面全部要鉴权 + 只允许跳板
② 关闭不必要的免密/共享
③ 关键系统用短时证书（不用长期密钥）
④ 内网分段 + 默认拒绝
⑤ 有"内网横向"检测规则（多目标连接/异常认证）
⑥ 定期跑"内网自查"（见自查清单）
```

### 检查清单

```
□ 无长期密钥散落在生产机
□ 免密关系最小化
□ 域管理员分层
□ Pod 不自动挂 SA token
□ 云实例角色最小权限
□ 中间件全部鉴权（含内网）
□ 2375 不暴露
□ CI/CD 强认证 + 凭据托管
□ 共享最小权限 + 无匿名
□ 内网分段 + 拒绝策略
□ 有横向移动检测
□ 定期内网自查
```
