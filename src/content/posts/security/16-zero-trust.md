### 传统边界模型的三个失效点

```
① 边界内部被当成"可信"（一个员工被钓鱼 → 内网随便扫）
② VPN 一旦连上就是"全内网可达"
③ 云与远程办公让"边界"消失
```

**零信任的核心假设是反过来的**：

```
① 网络位置不代表可信（在内网也不代表可信）
② 每次访问都要验证（不是登录一次就永久通行）
③ 最小权限（只给完成这件事需要的最小范围）
④ 假设已被入侵（设计时考虑"如果这台机器已被控"）
```

### 四层落地

**① 身份层：强认证**

```
- 密码 + MFA（最好是 FIDO2 硬件密钥）
- 单点登录（SSO）：所有系统统一入口
- 条件访问：异常地点/设备/时间 → 要求额外验证或拒绝
```

**"条件访问"是零信任与"传统 SSO"的关键差别**：

```
规则例：
- 从公司网段 + 已注册设备 → 直接通过
- 从境外 IP → 要求硬件密钥 + 管理员审批
- 从未注册设备 → 只允许访问低敏感应用
```

**② 设备层：设备可信**

```
- 设备注册（MDM/证书）
- 设备健康检查（补丁、磁盘加密、是否越狱）
- 设备证书做 mTLS（不只是用户名密码）
```

**没有设备层的零信任是"半截"**：攻击者拿到账号后，用自己的电脑就能进。

**③ 权限层：最小权限 + 动态授权**

```
- 按"应用 + 资源"授权，不是按"网络段"
- 权限有时效（临时授权，如"2 小时内可访问生产库"）
- 权限有审批（敏感操作走审批流）
- 定期回收（离职/换岗自动撤权）
```

**关键实践：Just-In-Time 权限**

```
平时没有生产权限
需要排查时申请 → 审批 → 开通 2 小时 → 自动回收
```

**④ 流量层：加密 + 逐次验证**

```
- 所有流量加密（不只对外，对内也加密）
- 服务之间 mTLS（不只靠"在内网"）
- 微隔离（东西向流量默认拒绝）
```

`mTLS` 的落地难点是**证书管理**（签发、轮换、吊销），通常用 SPIRE/cert-manager/服务网格来做。

### "有了 VPN 就够了吗"

**不够，理由**：

```
① VPN 给的是"网络可达"，不是"应用授权"
   → 连上 VPN 就能扫全内网

② VPN 是"一次认证、长期有效"
   → 会话被劫持/设备被控后，攻击者一直能用

③ VPN 无法做"按应用的最小权限"
   → 通常只能按网段分
```

**VPN 的正确位置**：它可以是"接入通道"的一层，但不是"授权"。

**替代/补充方案**：

```
- ZTNA（零信任网络访问）：按应用授权，不暴露整个网段
- 应用前置代理（如 Cloudflare Access / Teleport）：每个应用单独鉴权
```

### 落地路线（按投入从小到大）

```
第 1 步：SSO + MFA（覆盖所有系统）
第 2 步：关掉"内网免登录"（所有系统都走 SSO）
第 3 步：条件访问（异常设备/IP 要求加强验证）
第 4 步：设备注册 + 健康检查
第 5 步：ZTNA 替代"全隧道 VPN"
第 6 步：服务间 mTLS + 微隔离
第 7 步：JIT 权限 + 自动回收
```

**第 1、2 步的收益最大**：绝大多数入侵是"账号被盗 + 内网免登录"。

### 现实中的阻力

**① 用户体验**

```
"每次都要多点两下" → 业务方反对
```

对策：**条件访问**（正常场景无感，异常场景才加验证）。

**② 老系统不支持 SSO**

```
对策：用反向代理做统一认证（如 oauth2-proxy），老系统不用改
```

**③ 设备管理覆盖不全**

```
BYOD（个人设备）无法注册 → 给它"低权限通道"（只能访问邮件/文档）
```

**④ 运维自己的权限被收走**

```
运维会抵触"不能随时上生产"
对策：JIT + 审计（不是"不给"，是"给但有记录、有时限"）
```

### 反面案例：只做了"零信任"的一半

```
场景：上了 SSO + MFA，但内网数据库还是"密码 + 白名单 IP"
→ 攻击者从一台被控的跳板机连数据库（IP 在白名单）
→ 零信任完全失效
```

**零信任的检查点要看"最弱的那条路径"，不是"最漂亮的那个系统"**。

### 检查清单

```
□ 所有系统走 SSO（关掉内网免登录）
□ MFA 覆盖（关键系统用硬件密钥）
□ 有条件访问（异常场景加验证）
□ 设备注册 + 健康检查
□ VPN 不再等于"全内网可达"（用 ZTNA 或应用代理）
□ 东西向流量加密（mTLS）与默认拒绝
□ 权限按应用授，不按网段
□ 敏感操作 JIT + 审批 + 自动回收
□ 有审计日志（谁、何时、访问了什么）
□ 检查最弱路径（不只看最完善的系统）
```
