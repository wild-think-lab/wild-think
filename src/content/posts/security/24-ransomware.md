### 判定与第一反应

**判定信号**：

```
① 大量文件变成奇怪扩展名（.locked/.xxx）
② 桌面出现勒索说明（README/RECOVER.txt）
③ 文件打不开、内容被替换
④ 磁盘 IO 突然爆高（加密过程）
```

**第一反应必须做的三件事**：

```
① 断网（拔网线/封 VLAN）—— 阻断横向扩散
② 不关机（保留内存与进程状态）
③ 报告 + 拉起应急组（不要自己一个人搞）
```

**"先关机"是错的**：

```
关机可能触发"引导级加密"，也可能丢失内存证据
```

### 前 30 分钟不要做的事

```
✗ 不要付钱（先评估是否有可用备份）
✗ 不要用"解密工具"乱试（可能二次破坏）
✗ 不要在原机器上"恢复备份"（可能备份也被加密）
✗ 不要格式化重装（先取证）
✗ 不要重启（可能有开机脚本续加密）
```

### 三条并行的工作线

```
① 遏制：隔离感染主机、封端口（445/139/RDP）、打补丁
② 取证：保留内存/磁盘镜像、看日志（怎么进来的）
③ 恢复：确认备份可用 → 在隔离环境恢复 → 逐步回生产
```

**"三线并行"** 比"先查清再动手"更快恢复业务。

### 防控四条防线

**① 边界**

```
RDP 不暴露公网（或前置 VPN + MFA）
关闭 445/139 出网
邮件网关拦截宏/压缩包
```

**"RDP 暴露公网"是勒索的头号入口**。

**② 主机**

```
补丁（尤其 SMB/永恒之蓝类）
最小权限（不用域管理员日常登录）
LSA 保护 / 凭据保护
EDR/HIDS
```

**③ 账号**

```
域管理员分层（ tier 0/1/2）
禁止用同一账户登录工作站与服务器
定期改密 + MFA
```

**④ 备份（最后一道）**

```
离线备份（物理隔离/不可写介质）
备份账号与生产账号分离
备份验证（定期恢复演练）
```

**"备份可写 → 勒索会一起加密"**，这是最惨的一种。

### 五个"越救越糟"的操作

**① 用同一个域管理员账户去恢复**

```
凭据已在攻击者手里 → 恢复过程中再次被加密
```

**② 备份挂载在生产网络**

```
NAS 一直挂着 → 加密脚本顺手把备份也加密
```

**③ 直接重装后立刻回生产**

```
漏洞没修、入口没堵 → 几天后再次中招
```

**④ 只恢复数据，不改密码**

```
攻击者保留的凭据还能再进来
```

**⑤ 没做"从哪进来的"分析**

```
不修入口 = 必然复发
```

### 恢复顺序

```
① 隔离环境（独立网段）搭建
② 恢复 AD/域控（如果受影响）
③ 恢复关键业务（按依赖顺序）
④ 重置全部相关账户密码（含服务账号）
⑤ 打补丁、关端口、加固
⑥ 分批接入生产网络
⑦ 观察 72 小时（有没有残留）
```

**"先恢复域控"** 是 Windows 环境的关键（否则其他机器加不进域）。

### 事后

```
① 出报告（时间线/入口/影响/损失/恢复耗时）
② 复盘：哪条防线失效
③ 整改清单与截止日期
④ 演练：把"恢复流程"真正跑一遍
```

**"演练过"的团队恢复时间通常是一天，没演练过是一周**。

### 检查清单

```
□ RDP/SSH 不暴露公网（或前置 MFA）
□ 445/139 不出网
□ 补丁及时（尤其高危）
□ 域管理员分层 + 不用日常账户
□ EDR/HIDS 覆盖
□ 离线备份（不可写）
□ 备份凭据与生产分离
□ 定期恢复演练
□ 有应急预案（谁做什么）
□ 隔离网段与恢复流程已定义
□ 事后复盘与整改闭环
```
