### 先去掉神秘感

等保 2.0 就是一套**分级的安全要求清单**，核心逻辑：

- 数据越重要，要求越高（一级到五级，企业常见是二级和三级）。
- 每个要求都问三件事：**有没有做、做得对不对、能不能证明**。

第三条最要命。做了但拿不出记录（日志、配置截图、制度文件），在测评里等于没做。

### 技术要求的五大块

| 类别 | 管什么 | 典型要求 |
| --- | --- | --- |
| 安全物理环境 | 机房 | 门禁、消防、供电、防雷 |
| 安全通信网络 | 架构与传输 | 区域划分、带宽冗余、传输加密 |
| 安全区域边界 | 边界防护 | 防火墙、入侵检测、访问控制、恶意代码防范 |
| 安全计算环境 | 主机与应用 | 身份鉴别、访问控制、审计、入侵防范、数据完整性 |
| 安全管理中心 | 集中管控 | 集中审计、集中管控、集中告警 |

三级在二级基础上额外强调：**审计记录保护、集中管控、双因素认证、数据备份与恢复、剩余信息保护**。

### 最常扣分的十个点

1. **身份鉴别**：只有一个口令，没有双因素（三级要求 `administrator`、`root` 等管理账号必须双因素）。
2. **口令策略**：长度不足、没有复杂度、没有定期更换记录。
3. **登录失败处理**：账号锁定策略只在文档里，实际没配。
4. **审计覆盖不全**：只开了系统日志，没有对重要用户行为、重要命令的审计。
5. **审计记录可被删除**：日志存在本机、运维有权限删，且没有异地留存。
6. **入侵防范**：没有恶意代码防范（主机杀毒或 HIDS），或病毒库长期未更新。
7. **边界访问控制**：防火墙策略存在"any-any"，或默认允许。
8. **数据完整性/保密性**：重要数据传输明文、存储明文（如数据库口令字段）。
9. **备份恢复**：有备份但**从未做过恢复演练**，拿不出演练记录。
10. **集中管控**：三级要求日志集中收集分析，很多单位还是各自为政。

### 把要求翻译成配置

举三例，都是最容易被卡住的：

**双因素认证（三级）**

```bash
# Linux 管理登录叠加 Google Authenticator（PAM）
sudo apt install libpam-google-authenticator
google-authenticator          # 每账号跑一次，绑定手机

# /etc/pam.d/sshd 首行加入
auth required pam_google_authenticator.so

# /etc/ssh/sshd_config
ChallengeResponseAuthentication yes
AuthenticationMethods publickey,keyboard-interactive
```

**安全审计**

```bash
# auditd 规则：重要文件变更 + 命令执行
cat > /etc/audit/rules.d/hardening.rules <<'EOF'
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/sudoers -p wa -k sudo
-a always,exit -F arch=b64 -S execve -k exec
EOF
sudo augenrules --load
sudo systemctl enable --now auditd
```

日志转发到集中服务器：

```bash
# /etc/rsyslog.d/50-forward.conf
*.* @@10.10.10.50:514
auth.* @@10.10.10.50:514
```

**剩余信息保护 / 数据备份**

- 存储加密：云盘开加密，Linux 用 LUKS，数据库字段级加密（如手机号）。
- 备份：本地 + 异地，每月恢复演练一次，**留记录**（这是测评要看的东西）。

### 管理要求也别忽略

技术做完了，管理部分经常一片空白：

- 安全管理制度（含发布记录）
- 人员安全管理（入职离职流程、保密协议）
- 系统建设管理（上线前安全评估）
- 系统运维管理（变更记录、日志审计记录、漏洞扫描报告）

这些不需要多复杂，但**必须有文件、有日期、有签字**。模板可以从网上找，改成自己单位的名字，别一字不改交上去。

### 自查清单（可以直接拿去跑）

```
[ ] 管理账号是否双因素
[ ] 口令策略：长度≥8、三类字符、90 天更换
[ ] 登录失败 5 次锁定，锁定时间≥10 分钟
[ ] auditd 开启，覆盖账号/权限/命令执行
[ ] 日志集中收集，保留≥6 个月
[ ] 防火墙默认拒绝，策略无 any-any
[ ] 主机 HIDS 或杀毒运行中，库为最新
[ ] 重要数据传输 TLS，存储加密
[ ] 备份每日执行，异地存放，演练有记录
[ ] 漏洞扫描每季度一次，高危已修复
[ ] 三级：集中管控平台（日志+告警+策略）
```

### 测评前的两周怎么过

1. 先跑一遍上面的清单，把"能 5 分钟修好"的先修（口令、防火墙、日志）。
2. 补齐证据：配置截图（带时间）、日志样本、演练报告、制度文件。
3. 找一次预评估（内部或第三方），把明显问题挡在外面。
4. 测评当天，准备好**三张图**：网络拓扑、区域划分、数据流向。沟通效率翻倍。

等保不是"买个设备就过关"，它是**让你把已有的安全措施变成可证明的状态**。做完这一轮，系统的安全水平确实会上升一个台阶——这是它最实在的价值。
