"这台机器只开了 22 和 443"，说完这句话之后通常会查出第三个。暴露面管理的核心不是技术手段，而是**有没有一份和现实一致的清单**。

## 一、先把"实际开着什么"测出来

别相信配置，相信探测。从外部视角扫，而不是在机器上 `ss`。

```bash
# TCP 全端口 + 服务指纹（外部视角，从另一台机器发起）
nmap -sS -p- --min-rate 2000 -T4 10.0.0.9 -oA scan-tcp

# 常见 UDP 服务（数量少但别漏，161/53/123 是重灾区）
nmap -sU --top-ports 50 10.0.0.9 -oA scan-udp

# 版本探测，用于判断是不是该暴露的服务
nmap -sV -sC -p 22,80,443,3306,6379 10.0.0.9
```

外部扫到、机器上看不到的端口，通常是云安全组或主机防火墙在拦——**这说明收敛已经生效，不是异常**。反过来，机器上开着但外部扫不到，说明有防护；机器上开着、外部也扫得到，才是真正要处理的。

用 `ss` 对账：

```bash
ss -lntup | sort -k4
# 关注 0.0.0.0 与 127.0.0.1 的区别：前者对全网开放，后者仅本机
```

`0.0.0.0:6379` 是历史上最贵的一行输出。

## 二、给每个端口填三列：进程、归属、必要性

| 端口 | 进程 | 归属 | 必要性 | 处理 |
| --- | --- | --- | --- | --- |
| 22 | sshd | 运维 | 必须（限源 IP） | 改非标端口 + 密钥 + fail2ban |
| 3306 | mysqld | DBA | 仅内网 | 绑 127.0.0.1 或内网网卡，禁止 0.0.0.0 |
| 6379 | redis | 中间件 | 仅内网 | `bind` + `requirepass` + ACL |
| 9200 | elasticsearch | 日志 | 仅内网 | 绑内网 + 开 X-Pack 基础认证 |
| 8080 | 某遗留应用 | 无人认领 | 待定 | 先隔离，再确认 |

**"无人认领"是最危险的一栏**。处理原则：先做访问控制把它关进笼子，再给两周窗口期让业务方认领，到期未认领就下线——而不是"因为不确定所以留着"。

## 三、五个高频遗漏点

1. **IPv6**：只配了 `iptables`，机器却有公网 IPv6，服务照样对外可达。`ss -lntup` 里出现 `[::]:80` 就要当心。
2. **UDP**：SNMP（161）、NTP（123）、DNS（53）常被当作"无害"，实际是信息泄露与反射攻击的来源。
3. **容器的端口映射**：`docker run -p 8080:80` 默认绑 `0.0.0.0`，即使宿主机防火墙有规则也可能被绕过（DOCKER 链在 FORWARD 之前）。写 `-p 127.0.0.1:8080:80`。
4. **开发/调试端口**：`--debug`、`actuator`、`phpinfo`、K8s dashboard、Jenkins 未授权，上线时忘了关。
5. **备份与同步端口**：rsync 873、FTP 21，权限往往是"整个目录只读"，泄露量比数据库还大。

## 四、收敛动作的优先级

```text
P0（今天做）：公网暴露的数据库 / 缓存 / 管理后台 → 立即加白名单或关闭
P1（本周做）：SSH 加固、关闭无用服务、容器端口改绑 127.0.0.1
P2（本月做）：统一基线、把端口清单纳入变更流程
P3（持续）：周期扫描 + 与清单比对，产出差异报告
```

SSH 加固最小集：

```bash
# /etc/ssh/sshd_config
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
AllowUsers deploy
```

改完必须 `sshd -t` 校验再 reload，且**保留一个已登录会话**做兜底——这是唯一不会把自己锁在门外的做法。

## 五、把"清单"变成机制

手工扫一次只能证明"今天没问题"。要让它持续成立，需要三件事：

1. **端口清单入版本库**：`inventory/hosts.yml` 里写每个主机的期望端口，谁开的谁负责；
2. **周期扫描做差异**：`nmap` 结果与清单对比，新增端口即告警；
3. **上线卡口**：新服务上线必须声明监听地址与端口，默认绑回环。

差异检查可以用一条命令跑起来：

```bash
# 期望清单：每行 "host port"
comm -13 <(sort expected.txt) <(awk '/open/{print $1, $2}' scan-tcp.nmap | sort)
# 输出即"清单里没有但实际开着的端口"
```

## 六、验证收敛是否真的生效

三个视角都要测：

| 视角 | 手段 | 通过标准 |
| --- | --- | --- |
| 公网 | 外网机器 nmap | 只剩预期端口 |
| 内网横向 | 内网另一台机器 nmap | 数据库/缓存不可直连 |
| 主机自身 | `ss -lntup` + `ip6tables -L` | 与清单一致，无 0.0.0.0 意外监听 |

补一条：**用业务账号而非 root 做验证**，权限差异会暴露"能连但无权"的中间态。

> 一句经验：**暴露面收敛的产出不是"关掉几个端口"，而是一份带责任人的清单和一条能自动比对差异的流水线**。没有清单，三个月后一定回到原点。
