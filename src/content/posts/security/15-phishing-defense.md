### 为什么技术手段挡不住

```
钓鱼攻击的目标不是"系统漏洞"，是"人的判断"
```

三个现实：

```
① 邮件网关能拦一半，另一半靠"看起来像真的"
② 伪装成"老板/客户/HR"的消息，技术上无法判定真假
③ 一次成功点击就可能拿到账号，之后攻击者用合法身份活动
```

### 五个识别点（教给每个同事）

**① 发件人域名"很像但不一样"**

```
看起来：it-support@company.com
实际：  it-support@cornpany.com（rn 换成 m）
或：    it-support@company.com.evil.cn
```

**② 紧急 + 要求你做反常的事**

```
"你的账号将在 2 小时内被停用，请立即点击以下链接验证"
"这是老板要的付款，今天必须完成，不要打电话确认"
```

**紧急感是社工的核心武器**：它让你跳过核实。

**③ 链接显示与实际跳转不一致**

```
显示：https://company.com/login
实际：https://company.com.evil.cn/login
```

鼠标悬停看真实地址（手机上长按）。

**④ 附件类型可疑**

```
危险：.exe .scr .js .hta .lnk .iso .html（带脚本）
相对安全：.pdf .docx（仍可能带宏）
```

**⑤ 要求输入密码/MFA 码**

```
任何通过邮件要求你"输入密码"或"提供验证码"的，一律视为钓鱼
正规系统不会这么做
```

### 三种常见伪装

**① 仿冒登录页（最有效）**

```
点击链接 → 打开一个"和公司 SSO 一模一样"的页面
→ 输入账号密码 → 被记录 → 攻击者立即登录
（有的还会实时转发 MFA 码，绕过 TOTP）
```

对策：

```
① 用 FIDO2/WebAuthn 硬件密钥（ phishing-resistant：域名不匹配就不会响应）
② 强制从固定入口（书签/门户）登录，不点邮件里的链接
```

**② 仿冒内部消息（IM 钓鱼）**

```
"财务共享了一个文档，请查看" → 链接要求 OAuth 授权
→ 授权后攻击者拿到你的云盘/邮箱权限（不需要密码）
```

这类叫 **OAuth 授权钓鱼**，密码和 MFA 都挡不住。

对策：云平台的第三方应用授权要有管理员审批。

**③ 供应链/供应商邮件**

```
伪装成"客户发来的对账单.pdf"→ 实际是可执行文件
或伪装成"会计事务所的发票系统升级通知"
```

### 邮件网关能做/不能做

| 能做 | 不能做 |
| --- | --- |
| 拦已知恶意域名/IP | 拦住新注册的仿冒域名 |
| 沙箱分析附件 | 分析"纯文本社工话术" |
| DMARC/SPF/DKIM 校验 | 拦住"用合法邮箱被盗后发出的邮件" |
| 附件类型策略 | 拦住"看起来正常的 PDF 里嵌链接" |

**DMARC 是基础但不够**：

```
SPF：声明哪些 IP 可以代表你的域名发信
DKIM：给邮件签名
DMARC：告诉接收方"没通过校验怎么办"（none/quarantine/reject）
```

自己域名的 DMARC 至少要 `p=quarantine`，否则别人可以随便伪造你的域名发信。

### "点了链接"之后的三分钟

```
00:00  立即断网（拔网线/关 WiFi）—— 如果不确定是否已执行了东西
00:30  用另一台设备改密码（不要用被感染机器）
01:00  检查登录记录（邮箱/SSO/云控制台）
02:00  检查是否有新授权（OAuth 应用、API key、转发规则）
03:00  上报安全/IT，说明点了什么、输入了什么
```

**关键第一步是"用另一台设备改密码"**：在被感染的机器上改密码，密码会被记录。

### 检查登录与授权

```
邮箱：
- 登录历史（IP/地点/设备）
- 转发规则（攻击者常设"自动转发到外部"）
- 签名/自动回复是否被改

云平台：
- 第三方应用授权列表
- API key / AccessKey
- 新增的管理员

SSO：
- 活跃会话（踢掉可疑会话）
- MFA 设备变更记录
```

**"自动转发规则"是最隐蔽的持久化**：攻击者加了转发，之后所有邮件都抄送给他，你完全不知道。

### 组织层面的四件事

```
① 每季度发一次"模拟钓鱼"（不是考核，是训练；点中的人给 5 分钟微课）
② 新员工入职必讲（含真实案例）
③ 建立"可疑邮件一键上报"按钮（比让人转发给 IT 有效）
④ 关键岗位（财务/HR/高管）加强：硬件密钥 + 转账双人确认
```

**模拟钓鱼的注意点**：不要用"惩罚"导向，会让人不敢上报（反而更危险）。

### 检查清单

```
□ 自有域名配了 SPF/DKIM/DMARC（p≥quarantine）
□ 邮件网关有沙箱与附件策略
□ 关键岗位用硬件密钥（phishing-resistant）
□ 云平台第三方授权需管理员审批
□ 有可疑邮件上报入口
□ 每季度模拟钓鱼 + 培训
□ 有"点了链接"的三分钟处置流程
□ 转账类操作有双人确认
```
