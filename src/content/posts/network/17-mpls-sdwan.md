### 先弄清三个概念

```
专线（Leased Line）：点对点，物理独占（价格高，质量稳定）
MPLS VPN          ：运营商提供的"虚拟专网"（多点互联，有 QoS）
SD-WAN            ：用互联网线路 + 加密隧道 + 智能选路
```

**它们解决的是"多分支机构互联"这同一件事**。

### MPLS 的两层

```
L2VPN（如 VPLS / VPWS）：给你一条"虚拟二层链路"，像同一交换机
L3VPN（IP VPN）        ：运营商网络里承载你的三层路由
```

**企业最常用 L3VPN**（CE 与 PE 之间跑 BGP 或静态路由）。

### 典型拓扑

```
分支 CE ──(接入线)── PE ── MPLS 骨干 ── PE ──(接入线)── 总部 CE
```

**角色**：

```
CE（Customer Edge）：企业的边界路由器
PE（Provider Edge）：运营商的接入路由器
```

**CE 与 PE 之间的两种模式**：

```
① PE 托管路由（静态/默认路由）→ 简单，但灵活度低
② CE 与 PE 跑 BGP（PE-CE BGP）→ 灵活，企业自己管路由策略
```

### BGP 在 MPLS 上做什么

```
① 交换各站点路由（企业自己的地址段）
② 控制优先路径（多线路时选主备）
③ 与互联网出口联动（默认路由注入）
```

**CE 侧最小配置（示意，Cisco 风格）**：

```
router bgp 65001
 neighbor 10.1.1.1 remote-as 65099        ! PE 的 AS
 network 10.10.0.0/16                      ! 本地网段
```

**PE 会用 BGP 的"VRF"隔离不同客户**，所以你的路由不会跑到别人那里。

### 典型故障：一个站点不通

```
排查顺序：
① 接入线是否断（物理/PON/光纤）
② CE 与 PE 的 BGP 是否 Established
③ 路由是否学到（show ip route / show bgp）
④ MPLS 标签路径是否正常（运营商侧，要找他们）
⑤ 该站点本地防火墙/NAT 是否拦
```

**"分支不通但总部正常"** → 多半是那个站点的接入线或 CE。

**"全站点都不通"** → 骨干或总部侧问题，要联系运营商。

**判断"是不是运营商的问题"**：

```bash
ping <对端 CE 的公网/接入地址>
traceroute <对端内网地址>
# 如果 ICMP 到 PE 就断 → 运营商侧
```

### SD-WAN：为什么越来越多人选它

**核心思路**：

```
用多条便宜的互联网线路（宽带/4G/5G）
+ 加密隧道（IPsec/WireGuard）
+ 智能选路（按应用/时延/丢包切换）
```

**优势**：

```
① 成本低（宽带比 MPLS 专线便宜很多）
② 开通快（不用等运营商施工）
③ 灵活（新站点插上设备即可）
④ 支持"混合云"（直连云服务，不回总部）
```

**劣势**：

```
① 质量依赖互联网（抖动/丢包不可控）
② 需要自己做运维（隧道、策略、监控）
③ 关键业务（语音/实时）仍建议保留专线
```

### 五个方案的成本对比（数量级示意）

| 方案 | 月成本 | 开通周期 | 质量 | 适合 |
| --- | --- | --- | --- | --- |
| MPLS 专线 | 高（按带宽阶梯） | 2–8 周 | 最稳定（有 SLA） | 核心站点、实时业务 |
| 点对点专线 | 高 | 2–6 周 | 稳定 | 两地数据中心互联 |
| 互联网 + SD-WAN | 低 | 1–3 天 | 中（可多线路冗余） | 大量分支、办公 |
| 云专线（云厂商） | 中 | 1–2 周 | 稳定 | 上云接入 |
| 纯互联网 + VPN | 最低 | 即时 | 差（不可控） | 临时/低要求 |

**现实答案通常是"混合"**：

```
总部 ↔ 数据中心：专线/云专线
分支办公：SD-WAN（双线冗余）
临时/远程：VPN 或 ZTNA
```

### 双线路冗余怎么做

```
① 两条不同运营商（避免同缆中断）
② 用 BGP 或 SD-WAN 做自动切换
③ 关键业务做"主备"而不是"负载均衡"（避免抖动）
```

**"同缆不同运营商"** 是常见坑：

```
两家运营商的线可能走同一根光缆 → 一起断
→ 要求"物理路由分离"（写进合同）
```

### QoS 的现实

```
在 MPLS 上：可以端到端保障（运营商支持）
在互联网上：只能"自己出口整形"，端到端不可控
```

**所以"语音/视频"仍建议走专线或云专线**。

### 与 ZTNA 的关系

```
SD-WAN：站点到站点（网络层）
ZTNA  ：人到应用（应用层，零信任）
```

**两者互补**：

```
分支互联用 SD-WAN
远程办公/外包用 ZTNA（不把整个内网暴露）
```

**"远程办公就开 VPN 全隧道"是过时的做法**。

### 检查清单

```
□ 分清专线/MPLS/SD-WAN 的定位
□ L2VPN 与 L3VPN 按需求选
□ CE-PE 用 BGP 还是静态（按灵活度）
□ 有"一站不通"的排查顺序（线→BGP→路由→标签→本地）
□ 能判断"是否运营商侧问题"
□ 分支用 SD-WAN（双线冗余）
□ 核心与数据中心保留专线
□ 双线要求"物理路由分离"
□ 实时业务走 QoS 可控链路
□ 远程办公用 ZTNA（不全隧道）
□ 有线路质量监控（时延/丢包）
```
