### 为什么运维要懂 BGP

```
① 多线机房/双线接入要靠 BGP 做智能选路
② 云上的"Anycast"、"全球加速"底层是 BGP
③ 看到"路由被劫持"的新闻，要知道在说什么
④ 排查"海外访问慢"时，需要看路由路径
```

**不需要会配，但要看懂。**

### 五个基础概念

```
AS（Autonomous System）：一个自治系统，一个 ASN 标识
  - 如中国电信 4134、阿里云 45102
  - 每个 AS 内部用 IGP（OSPF/ISIS），AS 之间用 BGP

eBGP：不同 AS 之间交换路由
iBGP：同一 AS 内部交换"外部路由"

对等（Peering）：两个 AS 互相交换路由
  - 免费对等（双方都受益，如两家 ISP 互联）
  - 付费对等（一方付钱给另一方，如企业向 ISP 买带宽）
```

### 为什么 BGP "不按最短路径"

```
OSPF 按"链路开销"选最短路径
BGP 按"策略"选路：
  ① 优先 AS 路径短（但可被策略覆盖）
  ② 优先特定对等方（如"优先走电信"）
  ③ 优先 MED/本地优先级
```

**运营商选路是商业决策，不是物理最优**：

```
你的流量走了一条"绕地球半圈"的路径，
可能只是因为两家 ISP 之间是免费对等（不花钱）
```

这就是为什么"换个出口 IP，速度天差地别"。

### 多线机房怎么实现

```
机房有电信 + 联通 + 移动三条线
→ 机房自己有一个 ASN（或从 ISP 申请一段 IP）
→ 向三个运营商都宣告同一段 IP
→ 外部用户访问时，由 BGP 决定走哪条线
```

**关键：宣告"你自己的 IP 段"**。

```
如果你的服务器用的是运营商给的 IP，
你无法自己做 BGP 选路（那段 IP 属于运营商）
```

**所以"BGP 多线"的前提是：有自己的 IP 段（PI 地址）+ 自己的 ASN**。

### 宣告与"路由劫持"

```
正常：你向对等方宣告 "1.2.3.0/24 在我这里"
劫持：别人也宣告 "1.2.3.0/24 在我这里"，且路径更短
→ 流量跑到别人那里
```

**为什么会发生**：

```
① 配置错误（把别人的段写进自己的宣告）
② 恶意劫持
③ BGP 本身没有认证机制（靠"信任"）
```

**防护**：

```
RPKI（资源公钥基础设施）：给 IP 段做密码学签名
  → 路由器校验"这个 AS 有权宣告这段 IP 吗"
  → 没签名/签名不符的宣告被丢弃
```

**这是目前最有效的防护**，大型运营商都在部署。

### 五个常见故障判断

**① 某个地区访问不通**

```bash
# 从本地看路径
traceroute -T -p 443 1.2.3.4
mtr -T -p 443 1.2.3.4       # 更持续地看

# 看外部视角的路径（在线工具/另一地域的机器）
```

**判断**：如果特定地区不通，但其他地区正常 → 大概率是 BGP 路由问题。

**② 路径"绕远"**

```bash
mtr -T -p 443 target
# 看经过的 AS（可以用 IP 归属查询）
```

**常见原因**：免费对等导致绕行；或某条链路拥塞后被切到备用路径。

**③ 宣告丢失（自己的 IP 在某些地方不可达）**

```bash
# 用公共 looking glass 查
# 如 https://bgp.tools / https://lookingglass.example
```

搜索你的 IP 段，看有几个 AS 能看到你的宣告。

**④ 双线切换后部分用户不通**

```
原因：TTL 未过期（旧路由还在缓存）
或：宣告被某个运营商过滤（如小于 /24 的段被丢弃）
```

**关键规则**：**IPv4 通常只接受 /24 及更大的段**（/25 会被很多运营商过滤）。

**⑤ 路由抖动（flapping）**

```
链路不稳 → BGP 反复撤销/宣告 → 全网路由表反复更新 → 影响面很大
```

对策：BGP 有"抑制"机制（route dampening），但配置不当会误伤。

### 看懂一份 BGP 路由

```
show ip bgp 1.2.3.0/24

BGP routing table entry for 1.2.3.0/24
Paths: (2 available, best #2)
  Advertised to update-groups:
     3
  65001 65002 65003
    10.0.0.1 from 10.0.0.1 (1.2.3.1)
      Origin IGP, metric 0, localpref 100, valid, external
  65001 65002
    10.0.0.2 from 10.0.0.2 (1.2.3.2)
      Origin IGP, metric 0, localpref 100, valid, external, best
```

**逐段读**：

```
"65001 65002"        AS 路径（经过的 AS 序列）
"from 10.0.0.2"      从哪个邻居收到的
"localpref 100"      本地优先级
"best"               选中的路由
```

**路径越短不一定 best**：`localpref` 更高会优先。

### 云上的 BGP 应用

**Anycast**：

```
同一段 IP 在多个地域宣告
→ 用户被路由到"最近"的那个（BGP 最短路径）
→ DNS/CDN 大量使用
```

**全球加速**：

```
在多个接入点宣告同一 IP + 内部专线回源
→ 用户就近接入，走专线到源站
```

**这也是"为什么海外访问突然快了"的原因**：路由从公网绕行变成了专线。

### 运维要掌握的三个命令

```bash
# 1. 看路径与丢包
mtr -T -p 443 -n target

# 2. 查 IP 归属与 AS
whois 1.2.3.4
# 或在线工具

# 3. 查宣告情况
# bgp.tools / 各家 looking glass
```

**`mtr` 比 `traceroute` 好**：它是持续的（能看到丢包率变化），traceroute 只采样一次。

**`-T -p 443` 的意义**：用 TCP 443 探测，绕过 ICMP 被限速/禁用的问题。

### 检查清单

```
□ 知道自己的 IP 段与 ASN（如果做 BGP）
□ 有自有 IP 段（PI），不是运营商分配的
□ 宣告段不小于 /24（IPv4）
□ 部署了 RPKI（防劫持）
□ 排查用 mtr -T -p 443，不用 ping
□ 知道用 looking glass 看外部视角
□ 理解"绕远"是商业选路，不一定是故障
□ Anycast/全球加速知道底层是 BGP
```
