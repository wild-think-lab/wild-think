### 怎么用这篇

每题三段：**答题顺序**（你要说的步骤）、**判断依据**（哪条数据决定结论）、**追问**（面试官常接着问什么）。

### 一、性能与故障

**1. 负载（load average）飙高，你怎么查？**

顺序：看核数 → 看 us/sy/wa → 区分 CPU 型与 IO 型 → 定位进程。

```bash
nproc; uptime
top            # 1 键看每核
vmstat 1 5     # r 队列、b 阻塞、si/so
pidstat -u -d 1
```

判断：`load > 核数` 且 `r` 队列长 → CPU 不足；`wa` 高 → IO 瓶颈；`b` 多但 CPU 空闲 → IO 或锁。

追问：**"load 高但 CPU 不高"是什么？** → IO 阻塞、D 状态进程、大量锁等待。

**2. 内存还剩多少？**

```bash
free -m        # 看 available，不是 free
```

`available` 才是"还能给新进程用"的量。`free` 小是正常的（页缓存占了）。

追问：**"OOM 怎么确认"** → `dmesg -T | grep -i 'killed process'`，容器看退出码 137。

**3. 磁盘满了怎么查？**

```bash
df -h; df -i               # 空间 vs inode
du -sh /* | sort -h | tail
lsof +L1 | head            # 已删除但仍被占用的文件
```

三类原因：真的写满、inode 用尽、文件被删但句柄未释放。

追问：**"删了大文件但 df 没降"** → 进程还持有 fd，重启进程或 `: > file` 截断。

**4. CPU 100%，怎么定位到代码？**

```bash
top -H -p <pid>       # 找线程
perf top -p <pid>
perf record -F 99 -p <pid> -g -- sleep 10 && perf report
```

追问：**"Java 进程怎么查"** → `jstack` 抓线程栈，对上 top -H 的线程 ID（转 16 进制）。

### 二、网络

**5. "网站打不开"，你的排查顺序？**

```
① DNS：dig / nslookup
② 连通：ping 网关 → ping 目标 IP
③ 端口：telnet / nc -zv
④ TLS：openssl s_client
⑤ 应用：curl -v 看状态码与响应头
```

追问：**"ping 通但端口不通"** → 防火墙、安全组、服务没监听（`ss -lntp`）。

**6. TIME_WAIT 很多，有影响吗？**

```bash
ss -ant state time-wait | wc -l
```

结论：主动关闭方才有 TIME_WAIT，60 秒后自动消失。危害是**占用本地端口**（连接同一目标时可能耗尽端口）。解法：用连接池 / `tcp_tw_reuse`。

追问：**"为什么不能开 tcp_tw_recycle"** → 在 NAT 环境下会误丢连接，已被移除。

**7. 一个 TCP 连接的完整过程？**

握手（SYN/SYN-ACK/ACK）→ 传输 → 四次挥手（FIN/ACK/FIN/ACK）→ 主动关闭方进 TIME_WAIT。

追问：**"半连接队列溢出会怎样"** → 新连接被丢，`netstat -s | grep -i listen` 有 overflow 计数。

### 三、系统与服务

**8. 服务起不来，怎么查？**

```bash
systemctl status <svc> -l
journalctl -u <svc> -n 50 --no-pager
```

四层：配置语法 → 端口占用 → 权限/依赖 → 资源限制。

追问：**"systemd 里服务启动成功但立即退出"** → `Type=simple` 与 `Type=forking` 混用，或没有前台进程。

**9. 定时任务没执行，怎么查？**

```
① crontab 是否在正确的用户下
② cron 服务是否在跑
③ 环境变量（cron 的 PATH 很短）
④ 脚本权限与 shebang
⑤ 看 /var/log/cron 或 journalctl -u cron
```

追问：**"手动能跑，cron 不行"** → 99% 是环境变量或相对路径。

**10. 一台机器要上线，你会做哪些加固？**

```
□ 关闭不必要服务与端口
□ SSH 禁密码、禁 root 登录、限源 IP
□ 防火墙默认拒绝
□ 时间同步（chrony）
□ 内核参数（somaxconn、文件句柄）
□ 日志与审计（auditd/journald 保留）
□ 自动安全更新策略
□ 监控 agent 与备份
```

### 四、存储与文件

**11. 软链接和硬链接的区别？**

硬链接：同一 inode 的另一个名字，不能跨文件系统、不能连目录，删一个不影响另一个。
软链接：路径指针，可跨文件系统，原文件删了就失效。

**12. RAID5 与 RAID10 怎么选？**

RAID5：空间利用率高（n-1），写有校验开销，重建时风险大（大容量盘重建可能失败）。
RAID10：性能好、重建快，空间利用率 50%。

判断：**数据库、高写入 → RAID10；归档、读多 → RAID5/6**。

### 五、脚本与自动化

**13. 统计 nginx 日志里访问量 Top 10 的 IP**

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
```

追问：**"要按小时统计呢"** → `awk` 取时间字段切小时，或 `cut -c1-13`。

**14. 写一个脚本，批量检查 10 台机器的磁盘使用率，超 80% 报警**

```bash
for h in web{01..10}; do
  u=$(ssh -o BatchMode=yes "$h" "df -h / | awk 'NR==2{gsub(/%/,\"\",\$5);print \$5}'")
  [ "${u:-0}" -gt 80 ] && echo "ALERT $h ${u}%"
done
```

要点：`BatchMode=yes`（免密失败即退出）、默认值处理、`set -euo pipefail`。

**15. `set -euo pipefail` 分别是什么？**

```
-e  命令失败即退出
-u  使用未定义变量报错
-o pipefail  管道中任一命令失败即整体失败
```

追问：**"哪些情况 -e 不生效"** → `if` 条件、`&&`/`||` 左侧、命令替换里的部分场景。

### 六、K8s 与容器（进阶）

**16. 容器和虚拟机的区别？**

容器共享宿主内核，靠 namespace 隔离视图、cgroup 限资源；虚拟机有独立内核。所以容器轻、启动快，但隔离性弱、不能跑不同内核。

**17. 容器里 PID 1 的问题？**

PID 1 对信号的默认处理特殊（会忽略 SIGTERM），且不回收僵尸进程。解法：用 `tini`/`dumb-init`，或应用正确处理信号。

**18. 镜像为什么分层？**

共享与缓存：相同基础层只拉一次，构建时未变的层可复用。代价是层数多会拖慢拉取。

### 七、软素质题

**19. 你做过最有价值的一次优化？**

结构：现象（具体指标）→ 根因（不是"配置错了"而是"为什么当时这么配"）→ 改动 → 前后对比 → 沉淀（文档/告警/流程）。

**20. 线上故障你先做什么？**

先定影响面（多少人、多严重）→ 止血（回滚/降级）→ 再查根因 → 复盘。

**21. 你怎么保证变更不出事？**

窗口 + 清单 + 回滚预案 + 灰度 + 监控观察期。70% 故障来自变更。

**22. 遇到不会的问题怎么办？**

说清"我会怎么查"（去哪查、用什么工具、找谁），比硬编答案可信。

### 八、容易被问倒的细节

**23. `kill -9` 与 `kill -15` 的区别？**

15（TERM）是可捕获的优雅退出，9（KILL）不可捕获、直接杀。**优先 15**，因为 9 可能丢数据、留锁文件。

**24. 为什么 `df` 和 `du` 对不上？**

三种：文件被删但进程持有、inode 与块统计口径不同、挂载点重叠（`du` 会跨挂载点）。

**25. `iptables` 与 `firewalld` 的关系？**

firewalld 是 iptables/nftables 的前端管理工具。看规则要 `iptables -L -n` 或 `nft list ruleset`，不能只看 `firewall-cmd`。

### 面试建议

1. **先说顺序，再说命令**：面试官听的是思路，不是命令拼写。
2. **给判据**：说"如果 r 队列长就…"比"用 top 看一下"得分高。
3. **不知道就说不知道，然后给查法**。
4. **准备两个真实案例**：一个性能、一个故障，能讲清因果链。
