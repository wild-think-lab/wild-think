### 虚拟化解决的不是"省钱"

它解决的是三件事：**硬件利用率**（一台物理机跑十台虚机）、**隔离**（测试环境弄坏不影响生产）、**可搬迁**（换硬件不用重装系统）。

云服务器本质也是虚拟化——只是那层被厂商藏起来了。

### 三条技术路线

| 方案 | 类型 | 强项 | 弱项 |
| --- | --- | --- | --- |
| VMware vSphere / ESXi | 商业 Type-1 | 生态成熟、vMotion、企业支持 | 授权贵（按 CPU/核心计费） |
| Proxmox VE（PVE） | 开源 Type-1（KVM + LXC） | 免费、Web 管理、快照/集群/备份齐全 | 企业支持弱、界面相对朴素 |
| 纯 KVM + libvirt | 开源 Type-1 | 完全可控、可深度定制 | 无现成管理面，全靠自己搭 |
| VirtualBox / VMware Workstation | Type-2（装在 OS 上） | 学习、实验方便 | 不适合生产，性能与管理都弱 |

### 选型的四个判断

1. **有没有合规/审计要求**：要厂商 SLA 与工单支持，选 vSphere。
2. **预算**：几十人小公司、预算为零，PVE 是最实际的答案。
3. **规模**：3 台以内物理机，PVE 单机就够；20 台以上要考虑集群、共享存储和运维人力。
4. **团队能力**：没人懂 Linux 就别上纯 KVM；PVE 至少给了 Web 界面和备份工具。

### 一份现实建议

```text
学习 / 家庭实验室：PVE（一台小主机就能跑，快照随手做）
30–100 人公司内网：PVE 两节点 + 一台 NAS（NFS 共享存储）
有商业软件与域环境：VMware + 域控，按厂商支持走
公有云：别自建，用云主机 + 对象存储
```

**最容易犯的错**：在小公司上 vSphere，结果没人会配 vMotion，授权费还年年交。

### 关键概念（都要懂）

| 概念 | 含义 | 为什么重要 |
| --- | --- | --- |
| Hypervisor | 直接管硬件的虚拟化层 | Type-1 性能接近物理机 |
| vCPU 超分 | 分配的虚拟核数 > 物理核数 | 超分过头会让所有虚机一起卡 |
| 快照 | 某一刻的磁盘状态 | 不是备份！快照链长了会严重掉性能 |
| 精简置备 | 磁盘按需增长 | 容易"看起来还有很多空间"然后写满 |
| 迁移 | 虚机换物理机运行 | 需要共享存储或在线迁移能力 |

### 快照不是备份

这是运维事故的高发点：

- 快照存在**同一块存储**上，存储坏了快照一起没。
- 快照链越长，写放大越严重，性能越差。
- 快照回滚会丢掉回滚点之后的所有数据。

正确姿势：**快照用于"变更前 30 分钟的后悔药"，备份用于"数据不能丢"**。两者都要有。

### 本章要点

- 虚拟化带来利用率、隔离与可搬迁，不是单纯省钱。
- 小公司/PVE、要支持/vSphere、要定制/纯 KVM。
- vCPU 超分与精简置备是最容易踩的两个坑。
- 快照 ≠ 备份，必须有独立备份。
