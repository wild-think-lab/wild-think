### 基础元字符

```
.        任意字符（不含换行，除非 s 模式）
\d \D    数字 / 非数字
\w \W    单词字符（[A-Za-z0-9_]）/ 非
\s \S    空白 / 非空白
[...]    字符类（[abc]、[a-z]、[^abc]）
^ $      行首 / 行尾
\b \B    单词边界 / 非边界
```

**`.` 默认不匹配换行**：

```
要匹配换行：加 s 标志（PHP/JS），或 Python 的 re.S，或 [\s\S]
```

### 量词

```
*        0 次或多次（贪婪）
+        1 次或多次（贪婪）
?        0 或 1 次
{n}      恰好 n 次
{n,}     至少 n 次
{n,m}    n 到 m 次
*? +? ?? {n,m}?   惰性（非贪婪）
*+ ++ ?+ {n,m}+   占有（不回溯，PCRE/Java 支持）
```

**贪婪 vs 惰性**：

```
<a>.*</a>     → 贪婪：匹配到最后一个 </a>
<a>.*?</a>    → 惰性：匹配到第一个 </a>
```

### 分组与引用

```
(...)        捕获组
(?:...)      非捕获组（不占编号，性能更好）
(?<name>...) 命名捕获组
\1 \2        反向引用（第 n 个捕获组）
(?P=name)    Python 命名反向引用
```

**例子**：

```
(\d{4})-(\d{2})-(\d{2})      → 年月日三组
(?:https?|ftp)://            → 不占编号的协议组
(?<year>\d{4})-(?<month>\d{2})
```

**"用非捕获组"是好习惯**：不需要引用时能减少开销。

### 断言（零宽）

```
(?=x)    正向先行：后面是 x
(?!x)    负向先行：后面不是 x
(?<=x)   正向后行：前面是 x（宽度必须固定）
(?<!x)   负向后行：前面不是 x
```

**常用场景**：

```
密码至少 8 位且含数字与大写字母：
^(?=.*\d)(?=.*[A-Z]).{8,}$

匹配不在引号里的逗号（简化版）：
,(?![^"]*"[^"]*(?:"[^"]*"[^"]*)*$)

只匹配"末尾不是斜杠"：
(?<!\/)$
```

**注意"后行断言宽度必须固定"**：

```
(?<=ab|c)  ×  宽度不定 → 报错（多数引擎）
(?<=ab)    ✓
```

### 常用模式集合

```regex
# 邮箱（实用版，不追求 RFC 完整）
^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$

# IPv4
^((25[0-5]|2[0-4]\d|1\d\d|[1-9]\d|\d)\.){3}(25[0-5]|2[0-4]\d|1\d\d|[1-9]\d|\d)$

# URL
^https?://[^\s/$.?#].[^\s]*$

# 日期 YYYY-MM-DD
^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$

# 时间 HH:MM:SS
^([01]\d|2[0-3]):[0-5]\d:[0-5]\d$

# 手机号（中国大陆）
^1[3-9]\d{9}$

# 身份证（18 位）
^\d{17}[\dXx]$

# 强密码
^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[\W_]).{8,}$

# 中文字符
^[\u4e00-\u9fa5]+$

# 十六进制颜色
^#(?:[0-9a-fA-F]{3}|[0-9a-fA-F]{6})$

# 千分位数字
^\d{1,3}(?:,\d{3})*(?:\.\d+)?$
```

**"邮箱正则"不必追求完美**：实用版 + 发验证邮件是更靠谱的方案。

### 性能：回溯是性能杀手

**问题模式**：

```
(a+)+       嵌套量词
(a|a)*      重叠选择
.*.*        多个贪婪
```

**为什么慢**：

```
匹配失败时，引擎会尝试所有组合 → 指数级回溯
```

**一个真实例子**：

```regex
^(a+)+$
```

对 `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!` 会跑到天荒地老（ReDoS）。

**修法**：

```
① 用占有量词 a++（不回退）
② 用原子组 (?>a+)
③ 简化模式（避免嵌套量词）
④ 加长度限制（处理前先截断）
```

**"用户可控的正则"是高危**（可在正则里注入导致 CPU 打满）。

### 十种语言的差异

| 语法 | PCRE/PHP | Python | JS | Go | Java |
| --- | --- | --- | --- | --- | --- |
| 命名组 | `(?<n>...)` | `(?P<n>...)` | `(?<n>...)` | `(?P<n>...)` | `(?<n>...)` |
| 命名反向 | `\k<n>` | `(?P=n)` | `\k<n>` | `(?P=n)` | `\k<n>` |
| 占有量词 | ✓ | ✗ | ✗ | ✗ | ✓ |
| 原子组 | ✓ | ✗（3.11 起支持） | ✗ | ✗ | ✓ |
| 后行变长 | 有限 | 否 | 否 | 否 | 否 |
| 默认 unicode | 视配置 | ✓（str） | 需 u 标志 | ✓ | 视配置 |

**Go 的 RE2 不支持回溯**：

```
✅ 不会有 ReDoS（线性时间）
❌ 不支持反向引用、后行断言
```

**Go 的这个取舍很值得学**：安全优先。

**JS 的 `g` 标志有状态**：

```javascript
const re = /a/g;
re.test("aaa");  // true
re.test("aaa");  // true（lastIndex 继续）
re.test("aaa");  // false（走到头，重置）
```

**"复用带 g 的正则导致结果不一致"是经典 bug**。

### 常用命令里的正则

```bash
# grep
grep -E 'pattern' file
grep -P 'pattern' file        # PCRE（GNU grep 支持）

# sed
sed -E 's/(a|b)/x/g' file

# awk
awk '/pattern/ {print $1}' file

# find
find . -regex '.*\.(log|txt)'

# ripgrep（推荐）
rg 'pattern' -g '*.log'
```

### 命名捕获的实际用法

```python
import re
m = re.match(r'(?P<year>\d{4})-(?P<month>\d{2})', "2026-11")
print(m.group("year"))   # 2026
```

```javascript
const m = "2026-11".match(/(?<year>\d{4})-(?<month>\d{2})/);
console.log(m.groups.year);
```

**命名组让代码可读性提升非常多**（尤其多组时）。

### 五个常见错误

```
① 忘了转义 . 与 (  )  [ ]  等元字符
② 中文环境下用 \w 匹配不到中文（\w 只含 ASCII）
③ 多行文本用 ^ $ 没加 m 标志
④ . 不匹配换行（忘了 s 标志或 [\s\S]）
⑤ 用户输入的正则没做长度/复杂度限制（ReDoS）
```

**"中文匹配"**：

```
匹配中文：[\u4e00-\u9fa5] 或 \p{Han}（多数现代引擎支持）
```

### 检查清单

```
□ 不追求"完美"的正则（用实用版 + 业务校验）
□ 不需要引用就用非捕获组
□ 多组时用命名组
□ 注意贪婪与惰性
□ 避免嵌套量词（ReDoS）
□ 用户可控的正则加长度限制
□ 跨语言时检查命名组语法
□ JS 的 g 标志注意 lastIndex
□ 中文用 Unicode 属性或范围
□ 复杂场景先写测试用例再写正则
```
