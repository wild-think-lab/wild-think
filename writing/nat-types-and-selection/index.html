NAT 不止一种：六类 NAT 的行为差异与选型

NETWORK 2026-11-07 · 6 min

静态 NAT、动态 NAT、NAPT、NAT Server、双向 NAT、CGNAT/NAT444 的行为、适用场景与验证方式各不相同，混用概念会导致"配置看着对但不通"。

“NAT 就是把内网地址换成公网地址”——这句话只对了一半。实际工程里有六类 NAT，各自的匹配顺序、端口处理、会话方向完全不同。

一、静态 NAT（一对一）

一个内网地址永久映射到一个公网地址，不涉及端口转换。

  • 行为：双向、对称，外部可主动发起。
  • 场景：对外提供固定服务的服务器，需要固定公网地址。
  • 特点：映射关系写死在配置里，与流量是否存在无关（端口不会被占用）。
# 华为
nat static global 203.0.113.10 inside 192.168.10.10
# 思科
ip nat inside source static 192.168.10.10 203.0.113.10

二、动态 NAT（地址池）

一组内网地址映射到一组公网地址，不转换端口，因此公网地址数少于内网主机数时会出现”地址耗尽，后续连接无法建立”。

  • 行为：通常是单向的（内→外），外部无法主动发起。
  • 场景：内网主机数 ≤ 公网地址数的中大型出口。
  • 特点：地址池是独占式分配，一个主机占用一个公网地址直到会话结束/超时。
ip nat pool PUBLIC 203.0.113.11 203.0.113.20 prefix-length 24
ip nat inside source list 1 pool PUBLIC

三、NAPT / PAT（端口复用，最常见）

多个内网地址共享一个公网地址，靠改写源端口区分会话。

  • 行为：单向（内→外），外部不能主动连入（除非另外做端口映射）。
  • 场景：绝大多数家用/中小企业出口，“Easy IP”就是它的设备侧实现。
  • 特点：内部维护”内网 IP:端口 ↔ 公网 IP:端口”的转换表；并发连接数受端口范围和会话表大小限制。
# 华为 Easy IP：直接把接口地址当公网地址用
nat outbound 3000
# 思科
ip nat inside source list 1 interface GigabitEthernet0/0 overload

验证要点：

# Linux 上看 conntrack 表，能直观看到端口改写
sudo conntrack -L -p tcp | head
sudo ss -tnp | head

常见误区：NAPT 之后，服务端看到的源 IP 全是同一个，基于源 IP 做限流/审计的方案会失效，需要在应用层改用账号维度或 X-Forwarded-For（前提是经过了可信代理）。

四、NAT Server / 端口映射（外部主动进入）

把公网 IP 的某端口映射到内网主机的某端口。它和 NAPT 是互补关系：NAPT 管出，NAT Server 管进。

  • 行为：单向（外→内），回程自动反向转换。
  • 场景：对外暴露 Web/SSH 等单个服务端口。
  • 特点：只映射指定端口；用 0.0.0.0 或全端口映射（DMZ 主机）安全性差，慎用。
# 华为
nat server protocol tcp global 203.0.113.10 8080 inside 192.168.10.20 80
# 思科
ip nat inside source static tcp 192.168.10.20 80 203.0.113.10 8080

五、双向 NAT（源与目的同时改写）

出入两个方向都做转换，典型用于：内网访问外部 SaaS 时既隐藏源地址，又把目的地址从虚拟 IP 换成真实 IP；或跨 VRF 场景。

  • 行为：一条流上存在两次改写，会话表条目更复杂。
  • 场景：多租户隔离、SD-WAN 出口、云上 VPC 对接。
  • 风险：排障时 tcpdump 抓到的地址”三处不一致”（客户端视角、中间设备视角、服务端视角），必须明确在哪一跳抓。

六、NAT444 / CGNAT（运营商级 NAT）

两级 NAT：家庭 CPE 做一级，运营商侧再做一级。目的是在公网地址池有限时支撑大量用户。

  • 行为：端到端不再有唯一公网 IP，外部无法直接连入。
  • 影响：P2P、远程桌面、部分游戏联机、IPv4 端口映射全部受限；需要靠 STUN/TURN/中继或 UPnP 穿透。
  • 现状：IPv6 普及后逐步减少，但存量很大。判断方法：查到的”公网 IP”与 traceroute 出口不一致，或多设备共享同一出口 IP。

七、选型速查

需求 选型
对外固定服务的服务器 静态 NAT
内部大量主机上网、公网地址充足 动态 NAT（地址池）
内部大量主机上网、只有 1 个公网地址 NAPT / Easy IP
外部访问内部单个端口 NAT Server / 端口映射
需要同时隐藏源并改写目的 双向 NAT
运营商大规模接入 NAT444 / CGNAT

八、NAT 的四个共性坑

  1. 会话表满：并发连接超限后新连接直接失败，表现为”时通时不通”。查 display nat session 数量与上限。
  2. ALG 与特殊协议：FTP、SIP、PPTP 需要应用层网关改写载荷内的地址；关掉 ALG 会导致控制通道通了但数据通道不通。
  3. 超时设置：TCP 会话默认超时较长，UDP 短，长连接业务（数据库、消息推送）必须调大，否则出现”静默断连”。
  4. 回程路径不对称：多出口环境下，如果回程没走同一台 NAT 设备，会话表查不到，包被丢。要么做策略路由固定回程，要么在两端都做 NAT。

排查 NAT 问题的顺序永远是：先确认是哪一类 NAT，再看会话表，最后抓包核对三处地址。跳过第一步，后面的命令都会白跑。
