项目：KingLinux 的设计取舍——为什么本地客户端比网页更难做对

PROJECTS 2026-11-25 · 5 min

一个面向教学的全栈本地客户端，难点不在功能列表，而在"多技术栈共存、可离线运行、可增量更新"这三件事上。这里记录关键决策与踩过的坑。

教学软件和业务系统的评价标准不同：业务系统看”能不能支撑业务”，教学软件看”能不能让学习者在没有网络、没有老师的情况下走完一条完整路径”。这条约束几乎决定了所有架构选择。

一、核心约束

  1. 必须离线可用：学习者环境往往没网、装不了依赖。
  2. 必须本地运行：浏览器网页版解决不了”我想看看真实的服务怎么起”这个问题。
  3. 必须能增量更新：内容库会一直长，不能每次让用户重下全部。
  4. 必须可裁剪：有人只想学 Linux，不想装一整套。

二、架构选择

最终形态：本地客户端（外壳）+ 内置内容库（结构化文档）+ 可选的后端服务示例。

┌─────────────────────────────────────┐
│  客户端外壳（窗口、导航、搜索）      │
├─────────────────────────────────────┤
│  内容层：章节树 + 代码块 + 实验步骤  │
├─────────────────────────────────────┤
│  运行层：本地服务示例（可启停）      │
├─────────────────────────────────────┤
│  数据层：本地 SQLite（进度/笔记）    │
└─────────────────────────────────────┘

关键取舍与理由：

决策 选择 理由
内容分发 打包进客户端 离线可用优先于体积最小
进度数据 SQLite 单文件、可备份、查询方便，不引服务器
内容更新 差量包 + 版本号 全量包会让老用户放弃更新
界面 左侧树形目录 + 编辑器风格 学习者熟悉 VS Code 的心智模型

三、内容模型：章节树而非一堆 Markdown

早期版本把文档当”一堆 md 文件 + 目录”，问题很快暴露：

  • 章节顺序靠文件名前缀，一改就乱；
  • 代码块无法被单独提取、无法被”运行验证”；
  • 搜索只能全文扫，命中定位到文件而不是知识点。

改成结构化模型：课程 → 章节 → 小节 → 内容块。内容块带类型（text、code、command、lab、quiz），这样：

  • 目录树由数据生成，顺序可控；
  • 代码块可单独统计（“本课程共多少个可执行片段”）；
  • 搜索能定位到小节标题 + 内容块摘要。
{
  "id": "linux-03-02",
  "title": "journald 与 rsyslog 的分工",
  "blocks": [
    { "type": "text", "md": "..." },
    { "type": "code", "lang": "bash", "code": "journalctl -u nginx -n 80" }
  ]
}

四、踩过的坑

1. 打包体积失控

首版把全部文档 + 依赖一起打包，安装包接近 400MB。原因不是内容多，是把运行时也打进去了。

做法：外壳与运行时分离，运行时按需下载；文档只保留纯文本（图片改为首次访问时缓存）。体积降到 80MB 量级。

2. 路径与编码

Windows 上中文路径、空格路径、C:\Users\... 的盘符是三个独立的坑。统一规则：内部一律用正斜杠的相对路径，落盘前再转换；所有配置文件强制 UTF-8 无 BOM。

3. 增量更新的”半更新”状态

差量包下载到一半断网，重开客户端后文件是脏的。做法：先落到临时目录 + 校验哈希 + 原子替换，失败则回滚到上一版本。没有这层保护，用户会进入”打不开也重装不了”的死局。

4. 学习者环境的差异

  • 没有管理员权限 → 不能写系统目录，数据必须落在用户目录；
  • 杀软误报 → 打包签名与减少自解压行为；
  • 屏幕小 → 树形目录必须可折叠。

五、可验证的验收标准

项 判据
离线可用 断网启动，内容可读、可搜索、进度可存
增量更新 从 v1 升到 v2，只下载差量，更新后可回滚
环境无损 卸载后不残留注册表与服务
启动性能 冷启动 < 3s（机械盘 < 6s）
内容正确 每条命令都在目标环境验证过，标注适用版本

六、后续方向

  1. 内容与外壳解耦：内容库变成可独立发布的数据包，同一外壳可承载不同课程。
  2. 实验环境半自动：给出一键起本地容器/虚拟机的脚本，把”讲解”和”动手”缝在一起。
  3. 进度可视化：按章节统计完成度，让学习者看到自己的路径长度。

一句话：教学软件最难的不是做出功能，而是让”没有网络、没有老师、没有管理员权限”的人也能完整走一遍。所有架构决策都从这条约束推导出来。
